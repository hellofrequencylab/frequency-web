# Frequency Experience (the mobile app)

The Frequency app for phones, in `mobile/`. Android first. It is the `DEF-MOBILE` build on the
`/api/v1` contract ([`APP-CONTRACT.md`](APP-CONTRACT.md)), and it also controls the CyberUnicorn 5000,
the owner's ESP32 NFC and RF gadget. Decided in [ADR-1865](DECISIONS.md). What is built and what is
left is tracked in [`BUILD-BACKLOG.json`](BUILD-BACKLOG.json) (`DEF-MOBILE`, `LIVE-1115`), never here.

Install and run: [`mobile/README.md`](../mobile/README.md).

## 2. Sharing `lib/contract`

The repo is not a workspace and stays that way. The app compiles against `lib/contract/index.ts` as
the web does, without copying it:

- **TypeScript:** `mobile/tsconfig.json` maps `@frequency/contract` to `../lib/contract/index.ts`, and
  maps `zod` to the app's own copy so the type check never needs the web's `node_modules`.
- **Metro:** `mobile/metro.config.js` watches `lib/contract/` only and resolves `@frequency/contract`
  to that file. It also resolves `zod` from `mobile/node_modules` when the contract imports it, so an
  EAS or CI build that never installed the web's dependencies still bundles, with one zod.
- **Rule kept:** `lib/contract/index.ts` imports zod and nothing else (`lib/contract/contract.test.ts`).
  The app pins the same zod version as the web. Bump them together.
- **Root tooling ignores the app:** the root `tsconfig.json`, `eslint.config.mjs` and
  `vitest.config.ts` exclude `mobile/`. The app has its own `pnpm typecheck`, `pnpm lint` and
  `pnpm test`.

## 3. Endpoints the app added

Both follow APP-CONTRACT §6: logic in `lib/`, the schema in `lib/contract/index.ts`, a thin route.

- `GET /api/v1/rewards`: `listMyLoyaltyCards` (the web's `/rewards` read) behind `LOYALTY_ENABLED`,
  plus `current_season_zaps` and `current_streak` from the caller's own profile row, which
  `authorizeCaller` already read under RLS. No new service-role read.
- `GET /api/v1/spaces/checkin-links`: `lib/spaces/checkin-links.ts`. `listOperatedSpaces`, then
  `ensureCheckinNode` and `signedNodeUrl` for each, as the caller (`asCaller`). Creating a Space's one
  check-in node on first read matches what opening its check-in settings on the web does.

## 4. The CyberUnicorn link

The device protocol is `cyberpunkunicorn-os/apps/remote/PROTOCOL.md` (v1). The phone half:

- **Framing:** `rpc {json}\n` out. `@rpc` replies and `@evt` events in. Every other line is Bruce's log
  and is ignored. A full-width `＠` prefix is accepted too. `mobile/src/device/protocol.ts` (tested).
- **Concurrency:** one request at a time per transport, each with a timeout of 5 s (8 s for
  `cli.run`/`hat.probe`, 12 s for the `frequency.*` tag commands). `mobile/src/device/client.ts`.
- **USB:** the CH340 at 115200 8N1. **DTR and RTS are set false once and never touched again**, because
  they drive the ESP32's EN and IO0 and asserting them resets the board. The Kotlin module exposes no
  way to set them. Bytes cross the bridge as base64; UTF-8 is decoded in JS with a streaming decoder.
- **Bluetooth LE:** react-native-ble-plx against Bruce's serial service
  `4371ec0b-3d43-49f9-b731-7c72a4a7bb91` / characteristic `d555ed97-bf2a-4f46-b3eb-d1fcdd7325e9`,
  advertised as `CU5K`. MTU 517 requested on connect, one write with response per line, and
  notifications joined and split on `\n`. Scans filter on the service UUID; the manifest sets
  `neverForLocation`.
- **Internet relay:** a disabled "coming soon" choice. The design is PROTOCOL.md §6 (Supabase Realtime
  channel `device:<id>`). The server pieces it needs (`/api/v1/devices/realtime-token`, Realtime RLS,
  device ownership, `GET /api/v1/me/devices`) are not built.
- `frequency.write_tag` is sent `{url}` only: the tag holds one NDEF URI record and nothing else
  (`docs/LOYALTY.md` §6). The URL is the server-signed `/n/` link, picked from the caller's Spaces or
  pasted, never built on the phone. A tag made in the app always checks someone in. `frequency.read_tag`
  reads it back and the app compares the URL.

## 5. Owner steps the app needs (not code)

- `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY` in `mobile/.env`
  (public values; `mobile/.env.example`).
- `frequency://auth/callback` on the Supabase Auth redirect allow-list for the magic link (`OWN-091`).
  The one-time code in the same email works without it, if the email template shows the code.
- An EAS project (`eas init`, sets `EAS_PROJECT_ID`) and Firebase `google-services.json` for an Android
  Expo push token. Without them the app says push is off and works otherwise.
- `ANDROID_SHA256_FINGERPRINTS` on the site (`LIVE-714`) so `https://frequencylocal.com/n/…` links open
  the app instead of the browser.
