# Frequency Experience (the mobile app)

The Frequency app for phones, in `mobile/`. Android first. Decided in [ADR-1865](DECISIONS.md). What is
built and what is left is tracked in [`BUILD-BACKLOG.json`](BUILD-BACKLOG.json) (`LIVE-1121`,
`DEF-MOBILE`), never here.

Two halves, two tabs. **Device** is the CyberUnicorn 5000 remote (owner scope, 2026-10-19: "Right now, I
just want a phone app to control it"): it needs no Frequency account and no network. **Frequency** is the
member experience on `/api/v1` ([ADR-1866](DECISIONS.md), §6): sign-in, Rewards, tap-to-check-in and
push. Install and run: [`mobile/README.md`](../mobile/README.md).

`android/` and `ios/` are generated by `expo prebuild` and gitignored. Native behaviour changes in
`app.config.ts` and `plugins/`, never in the generated folders. The manifest asks for Bluetooth (scan
with `neverForLocation`, connect) and USB host for the remote, and NFC, foreground location and
notifications for the member half (§6). Runtime settings are `EXPO_PUBLIC_*` variables
(`mobile/.env.example`); without them the app is the remote only and the Frequency tab says so.

## 2. Design: the Frequency system only

The app wears the **live Frequency theme**, the one the website renders under
`<html data-design="frequency">`. Values come from `app/themes/frequency.css` (the alias layer) over
`app/themes/frequency/core.css` (the export), plus the members kit (`kit-members.css`,
`members-ui.css`). Where the alias layer overrides the export (the cool canvas `#F4F6F7`, the teal
accent, the blue-to-aqua pastel, the AA-fixed muted text, the status hues), the alias layer wins,
because that is what a member sees. Faces, the icon sprite and the logos come from
`design_handoff/frequency/`. Rules kept: the pastel only for the one primary action, progress and live
dots; Unbounded at weight 500 only; sentence case and no em dashes in copy; no hex outside `tokens.ts`.

When the web theme changes, change the values in `tokens.ts`. The kit reads roles, so no component
changes.

## 4. The CyberUnicorn link

The device protocol is `cyberpunkunicorn-os/apps/remote/PROTOCOL.md` (v1). The phone half:

- **Framing:** `rpc {json}\n` out. `@rpc` replies and `@evt` events in. Every other line is Bruce's log
  and is ignored. A full-width `＠` prefix is accepted too. `mobile/src/device/protocol.ts` (tested).
- **Concurrency:** one request at a time per transport, each with a timeout of 5 s (8 s for
  `cli.run`/`hat.probe`, 12 s for the `frequency.*` tag commands). `mobile/src/device/client.ts`.
- **USB:** the CH340 at 115200 8N1. **DTR and RTS are set false once and never touched again**, because
  they drive the ESP32's EN and IO0 and asserting them resets the board. The Kotlin module exposes no
  way to set them. Bytes cross the bridge as base64; UTF-8 is decoded in JS with a streaming decoder.
- **Bluetooth LE:** react-native-ble-plx against Bruce's serial service
  `4371ec0b-3d43-49f9-b731-7c72a4a7bb91` / characteristic `d555ed97-bf2a-4f46-b3eb-d1fcdd7325e9`,
  advertised as `CU5K`. MTU 517 requested on connect, one write with response per line, and
  notifications joined and split on `\n`.
- **Tag writer:** signed in, the owner picks one of the Spaces they run and its signed check-in link
  comes from `GET /api/v1/spaces/checkin-links`; signed out, they paste it (Settings, Check in, Copy).
  Either way the app checks its `/n/<uuid>?s=` shape, warns on a host other than frequencylocal.com, and
  sends `frequency.write_tag {url}` only: one NDEF URI record and nothing else (`docs/LOYALTY.md` §6). It
  never builds or retypes the link. `frequency.read_tag` reads it back and the app compares the URL.
- **Internet relay:** a "coming soon" choice in Connect (`mobile/src/device/relay.ts`). The design is
  PROTOCOL.md §6.

## 5. Sharing `lib/contract`

The repo is not a workspace and stays that way. The app compiles against `lib/contract/index.ts` as the
web does, without copying it: `mobile/tsconfig.json` maps `@frequency/contract` to the file and `zod` to
the app's own copy, and `mobile/metro.config.js` watches only `lib/contract/` and resolves its `zod` from
`mobile/node_modules`, so a build that never installed the web still bundles. The app pins the web's zod
version. The root `tsconfig.json`, `eslint.config.mjs` and `vitest.config.ts` exclude `mobile/`. Today
only the Frequency tab reads from it (`CONTRACT_VERSION`), which keeps the path proven by every bundle.

## 6. The member experience (the Frequency tab)

Built in [ADR-1866](DECISIONS.md) from the first version at commit `73dc345f4`, on the kit. Every read and
write goes through `/api/v1` ([`APP-CONTRACT.md`](APP-CONTRACT.md)); supabase-js is for sign-in and the
session only, never for tables.

| Piece | How | Where |
|---|---|---|
| Sign-in | supabase-js email: a one-time code typed in the app, or the magic link that opens `frequency://auth/callback` (and `https://frequencylocal.com/auth/native`, APP-CONTRACT §11). PKCE, exchanged in the app. New accounts start on the web. | `sign-in.tsx`, `auth/callback.tsx`, `lib/supabase.ts` |
| Session | Expo SecureStore, in numbered chunks under 2 KB each (SecureStore's per-value limit). Auto-refresh only while the app is in the foreground. | `lib/secure-storage.ts` |
| Bootstrap | `POST /api/v1/session/bootstrap` after sign-in and on every cold start, so guest tickets and RSVPs land on the account. `profile_required` shows "One step left" with the web's `/onboarding`. | `lib/auth.tsx` |
| The contract's rules | On a `401` refresh once and retry; a second `401` signs out. Branch on `error.code`, never the message. Every answer parsed with its envelope schema. | `lib/api.ts` |
| Rewards | `GET /api/v1/rewards`: season Zaps and streak as stat tiles, every Regulars stamp card with its open reward codes, the same reads as the web's `/rewards`. `enabled: false` says Regulars is not open yet. | `(tabs)/frequency.tsx`, `components/rewards.tsx` |
| Check in | The phone's own NFC reader (react-native-nfc-manager) reads the venue tag's one URI record, or a pasted link, or the deep link a QR opens (`n/[id].tsx`); then `POST /api/v1/nodes/{id}/capture` with the signed code and, when allowed, the phone's location. The server decides; a refusal shows the verifier's reason in plain words. | `check-in.tsx`, `lib/phone-nfc.ts`, `lib/capture.ts`, `lib/node-link.ts` |
| Push | After the OS grants permission, the Expo push token goes to `POST /api/v1/push/devices` on every launch and is revoked on sign-out. Needs `EAS_PROJECT_ID` and, on Android, the build's Firebase config; without them it reports why and changes nothing. | `lib/push.ts` |
| Tag writer | Signed in, `GET /api/v1/spaces/checkin-links` lists the owner's Spaces with their signed links (§4). | `device/tag-writer.tsx` |

The two endpoints added for the app: `GET /api/v1/rewards` (`app/api/v1/rewards/route.ts`, `RewardsView`)
and `GET /api/v1/spaces/checkin-links` (`lib/spaces/checkin-links.ts`, run as the caller so a Space the
caller does not edit is left out). Both are listed in APP-CONTRACT §8 and tested in
`app/api/v1/rewards/route.test.ts`.

The device remote stays fully usable signed out, and with no `EXPO_PUBLIC_*` settings at all.
