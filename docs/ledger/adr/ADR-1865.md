## ADR-1865: Frequency Experience, the Expo app in `mobile/`, shares `lib/contract` without a workspace and also runs the CyberUnicorn remote (LIVE-1115)

**Status:** Accepted · 2026-10-19 · backlog `LIVE-1115`, `DEF-MOBILE` · owner request 2026-10-19 (relayed by the coordinating session): build the parked app now, Android first, as "Frequency Experience", combining the member experience with control of the owner's CyberUnicorn 5000. Builds on [ADR-1643](DECISIONS.md) (the contract) and [ADR-1650](DECISIONS.md) (the Expo / React Native stack).

**Context.** `DEF-MOBILE` was parked to 2027-01-05 with the stack decided and `/api/v1` built for it. The owner asked for the app now, on Android, and asked that the same app drive his ESP32 gadget over USB OTG or Bluetooth LE while the phone stays on its own Wi-Fi. APP-CONTRACT §6.2 says the app compiles against `lib/contract/index.ts` as it is, but the repo is a single Next.js package, not a workspace.

**Decision.**
1. **Where.** The app is `mobile/`, its own package (Expo SDK 58, Expo Router, pnpm with `node-linker=hoisted`). Generated `android/` and `ios/` are gitignored (Continuous Native Generation).
2. **Sharing the contract, smallest change.** No workspace. `mobile/tsconfig.json` and `mobile/metro.config.js` point `@frequency/contract` at `../lib/contract/index.ts` and resolve its `zod` from `mobile/node_modules`, so a build that never installed the web still type-checks and bundles. The app pins the web's zod version. The root `tsconfig.json`, `eslint.config.mjs` and `vitest.config.ts` exclude `mobile/`. Moving to a pnpm workspace stays available if a second shared package ever appears.
3. **Data only through `/api/v1`.** supabase-js is used for sign-in and the session (SecureStore, chunked past its 2 KB value limit) and nothing else. Every read and write is a contract call parsed with the endpoint's envelope schema.
4. **Two endpoints added for it**, both on the §6 pattern: `GET /api/v1/rewards` (the web's `/rewards` read, plus season Zaps and streak from the caller's own profile row) and `GET /api/v1/spaces/checkin-links` (each run Space's signed door link through `ensureCheckinNode`, as the caller).
5. **The device remote lives in the same app**, on protocol v1 from `cyberpunkunicorn-os/apps/remote/PROTOCOL.md`. USB is a local Kotlin Expo module over usb-serial-for-android that opens the CH340 at 115200 8N1 and sets DTR and RTS false once, with no API to change them (they reset the board). BLE uses react-native-ble-plx on Bruce's serial service. The internet relay is a disabled placeholder until the server pieces in PROTOCOL.md §6 exist.
6. **Design.** The Commons tokens and the Thermal night room are ported value for value into `mobile/src/theme/tokens.ts`. The icon sprite and the logos are generated from `design_handoff/frequency/assets/` by scripts, not redrawn.

**Consequences.** `DEF-MOBILE` stops being "no Expo project in the tree": the shell, NFC reading and the native push client exist. Store submission, App Attest / Play Integrity, Sign in with Apple, in-app purchase and iOS remain with `DEF-MOBILE`. Owner steps (EAS project, Firebase config for Android push, the `frequency://auth/callback` redirect on the Supabase allow-list, `ANDROID_SHA256_FINGERPRINTS`) are listed in `docs/MOBILE-APP.md` §5. A change to `lib/contract/index.ts` can now break the app's typecheck, so run `pnpm --dir mobile typecheck` when editing it. The USB and BLE paths are untested until they run against the real board.
