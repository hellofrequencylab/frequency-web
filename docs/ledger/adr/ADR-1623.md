## ADR-1623: A protected Loom image is shown only as a stored 480px proof object, never its original: protecting writes the proof, the Studio, the Space Loom Studio and the picker sign only that object, the picker never places it, and there is no watermark (LIVE-580)

**Status:** Accepted · 2026-09-29 · backlog `LIVE-580` (closed here) · child 5 of `PROG-D6` under [ADR-1562](DECISIONS.md) · builds on [ADR-1595](DECISIONS.md) (LIVE-577) and closes its two "until LIVE-580" consequences · **amends HYG-017's on-the-fly ruling ("nothing writes derivative files") for protected images only** (see Decision 2) · owner rulings 2026-09-29 ~03:45Z "Width-capped proof, no watermark" and ~19:10Z "Store a small proof file" · re-tested first per [ADR-1082](DECISIONS.md) · numbered 1623 by the orchestrator's assignment for this wave

**Context.** Re-tested on the LIVE-577 branch (`8df84fe36`), from the repo only (no database access). The premise held exactly: `renditionUrl` (`lib/library/rendition-url.ts`, [ADR-1496](DECISIONS.md)) rewrites `/object/public/` only and hands anything else back unchanged, so a private object had no rendition; the Studio page minted `signedLibraryAssetUrl` (the one-hour signed ORIGINAL) as each protected row's thumbnail and drawer image; and `listLoomScopeImages` dropped every row with no url, so a protected asset left the picker and the Space Loom Studio entirely, while a row flagged Protected whose file had not moved yet was still offered for placement with its public master. The first build signed the master with a storage transform, as the row planned. Then one fact was found in `supabase/storage`'s source, `getSignedObject` and `verifyObjectSignature`: a transform-signed token carries its transform, but the object route checks only the token's path, scope and expiry and ignores the transform. The same token therefore opens the master at `/object/sign/` until it expires, so a transform-signed proof caps what is displayed but leaves the original one path edit away. The owner ruled for a stored proof. How many rows are Protected today is not measured here (the orchestrator reports none left in `library-media`).

**Decision.**

1. **A proof is its own object.** `lib/library/proof-object.ts`: the proof of a master at `<space>/<file>` lives in `library-private` at `proofs/<space>/<file>` (`libraryProofPath`, deterministic, so no column and no migration). A proof link is a signed URL for that path. Storage checks the token's path on every route, so no edit of a proof link reaches the master.
2. **HYG-017 amended, for protected images only.** Renditions stay on the fly for everything else. A protected image gets exactly one written derivative, its proof, because a derivative that is only computed per request cannot be separated from the master's token.
3. **Storage resizes and nothing here decodes.** `writeLibraryProof` signs the master for one minute with `transform: { width: 480, resize: 'contain' }`, fetches it server-side (the link never leaves the server) and uploads the bytes storage returns as the proof. `sharp` stays out of the Loom seam: `check:og-trace` fails a route that traces it without rasterising a card, and the picker, the page editor and the importer reach this code (`docs/DEPLOY-SAFETY.md`, the `lib/library/ingest.ts` header). The owner's sketch named the repo's image tooling, and storage's transform is the tooling the Loom already uses for every rendition.
4. **The cap is checked on the bytes.** The proof's own header is parsed (`readImageDimensions`, byte parsing only). Anything wider than 480 px, of unreadable width, SVG, not an image, or over 2 MB is refused and never stored, so a proof file cannot be the master under another name whatever storage answered.
5. **The proof follows the protection.** `protectLibraryAsset` writes the proof once the master is private, before the public copies go, and releasing deletes it. Both are best-effort: a proof that failed to write is written lazily on the next render. Deleting a private asset (the Studio's delete, the Space Loom Studio's remove) deletes its proof too.
6. **One proof function.** `proofLibraryAssetUrl(asset, ttlSeconds)` in `lib/library/asset-urls.ts` behaves as follows:
   - A private protected row gets a signed link to its proof object, for an hour at most. Signing a missing object fails, and that failure is the cheap existence test: the proof is then written and signed.
   - A protected row whose file is still public gets null, because any link to it is a link to a public master; its drawer save moves the file.
   - A protected vector, a row with no file, or a proof that cannot be written gets null.
   - An unprotected row gets `renditionUrl(url, 'grid')`. Audio and video pass through; they cannot be private.
   It never signs the master for display.
7. **Every protected render goes through it.** The admin Studio page proofs every protected row for the grid and the drawer; it no longer signs the original. `listLoomScopeImages` (the personal scope) and `listSpaceLoomImages` (a Space scope, read on the caller's session since LIVE-571) keep a private protected row only when a caller asks (`includeProtected`). `withLoomProofs` swaps each protected row's url for its proof link, drops a row with none and strips the storage key before the list leaves the server. `loomImages` (the picker, and the Space Loom Studio's refresh) and the Space Loom Studio page use it.
8. **Renderable, never placeable.** The picker renders a protected tile with a Protected badge and a disabled button, so neither a protected asset nor an expiring URL is ever stored in a page ([ADR-1562](DECISIONS.md) §2). The Space Loom Studio shows the proof with the same badge.
9. **No watermark.** The owner closed the question: a burned-in mark is a decode, and the proof is a width cap.

**Rejected.**
- Signing the original and letting the browser scale it: the master reaches every viewer, which is the state this row replaces.
- A transform-signed link to the master: storage honours the token at the object route, so it is the Context's gap.
- A `proof_path` column and migration: the path is deterministic, so a column would add a migration and change nothing.
- `sharp` in the Loom seam: the og-trace fan-out.
- Offering a protected row for placement with its proof: a signed URL in a stored document expires under it.

**Consequences.**
- ✅ No surface renders a protected original, and no proof link can be edited into one: the Studio grid and drawer, the Space Loom Studio and the picker sign only `proofs/...`.
- ✅ A protected asset is back in the pickers and the Space Loom Studio as a locked proof, and a flagged row whose file is still public is no longer placeable.
- ⚠️ A protected asset flagged before its file moved shows no image until its drawer is saved.
- ⚠️ Until LIVE-578 lands, the Studio drawer's Open and Download of a protected row give the proof, not the original.
- ⚠️ Making a proof costs one server-side fetch and one upload per protected image. It counts once per billing cycle against Supabase's transformation quota, the same metering `renditionUrl` uses.
- ⚠️ A proof whose asset row was removed by a path other than the two delete doors stays in the private bucket, signed for nobody.
