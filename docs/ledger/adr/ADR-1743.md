## ADR-1743: An event's public JSON-LD publishes the venue when the host has not hidden the address

**Status:** Accepted · 2026-10-14 · owner-ruled · amends [ADR-186](DECISIONS.md), [ADR-825](DECISIONS.md), [ADR-1189](DECISIONS.md)

**Context.** The Event structured data on `/events/<slug>` was city-level only: city, region and country, never a venue name, street or map point. ADR-1189 records the split this rested on: ADR-186 owned "city-level public surfaces, and the JSON-LD carrying no venue", and ADR-825 hid the exact address on the event page until a viewer registers, noting the JSON-LD was unchanged. Most hosts never hide their address, so Google and answer engines got "Vista" for an event whose page, for a signed-in viewer, shows the street and a map. The owner ruled (2026-10-14) that the venue belongs in the structured data whenever the host has not hidden it.

**Decision.** (1) `eventSchema` (lib/jsonld.ts) adds the venue name (as the Place name), `streetAddress`, `postalCode` and a `GeoCoordinates` point from the event's stored `geog` to the Place, ONLY when `hide_address` is explicitly `false`. `publishableVenue` holds that rule in one place: a `true`, `null` or unread flag publishes the city-level Place exactly as before. Blank parts are omitted, never emitted as empty strings, and a point needs both coordinates in range. (2) The public page (`app/(public)/events/[slug]`) reads the venue through `lib/events/public-venue.ts`, a service-role read of one public, published, not-removed event that drops every venue column on the server when the address is hidden, so no caller can publish what it never received. The member page passes the event's own flag, never the viewer's registration, so both copies publish the same node. (3) The anon column revoke of `street, postal_code, geog, venue_name` (migration 20270330000000, SCAN-209) stays: the publishable key still cannot read a hidden address. (4) Event lists (city hubs, `/events`) stay city-level; they do not carry the flag.

**Not changed.** The visible pages. ADR-825's page rule (exact address for registered viewers or managers when hidden) is untouched. The anonymous public page `/events/<slug>` still shows the city line only, so for a visible-address event the structured data now carries more than that page displays; whether that page should show the venue it publishes is left to the owner rather than changed here.

**Consequences.** `lib/jsonld-event-venue.test.ts` pins: hidden emits no street or geo, visible emits them, unread is hidden, blanks are omitted. ADR-186's "the JSON-LD carries no venue" and ADR-825's "JSON-LD is unchanged" now read as the hidden-address case only; `lib/events/visible-location.ts`'s note that the JSON-LD is city-level holds for hidden addresses.
