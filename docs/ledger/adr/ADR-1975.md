## ADR-1975: sharp is stripped from every function that is not a share card, by one trace exclude

**Status:** Accepted, 2026-11-17 (HYG-245). Corrects one line of [ADR-1002](DECISIONS.md)'s "what does not work" table.

**Context.** Production dpl_9hr5MSWb (#5182) wrote 7.99 GB of its 8 GB `check:build-budget`, so any PR adding one route failed. The largest single line was libvips-cpp.so, 909 MB (17.8 MB x 51 functions). `check:og-trace` split those 51 into 28 card routes that rasterise and 23 page functions that carry sharp only because they share a segment with a per-entity `opengraph-image.tsx`: the page's metadata module imports the card module for its `alt`, `size` and `contentType`, and nft reads `import('sharp')` out of that chunk. Moving the cards to explicit image routes would cure it, but about 25 probes and tests pin the card paths and the owner parked that move until after the Jan 1 launch (HYG-245, 2026-11-16).

ADR-1002 recorded `outputFileTracingExcludes` as unusable here because "a negation matches everything" in picomatch's `contains` mode. That is true of a bare negation (`!opengraph-image`) and false of a path-shaped one. Measured with Next 16.4.6's own compiled picomatch and `normalizeAppPath` over every route in app/: `!**/@(opengraph-image|twitter-image)*` matches 614 routes and leaves out exactly the 28 card routes.

**Decision.** `next.config.ts` excludes `node_modules/sharp/**` and `node_modules/@img/**` (top level and under `.pnpm`) from every route matched by that key. It is safe by construction: `lib/og/deliver.ts` is the only module that imports sharp, it does so lazily inside `deliverCard`, and only card routes call `deliverCard`. `check:build-budget` now also prints its full ranked cost list and the headroom on a passing run, so the next cut is readable from any build log instead of only from a failed one.

**Consequences.** About 410 MB leaves the deploy (23 x 17.8 MB plus sharp's own binding), with no route path, probe or card changed. `check:og-trace`'s incidental count falls to about 0. A future non-card route that needs sharp would have it stripped and fail soft; the config comment says to name it in the key, and `scripts/sharp-trace-exclude.test.ts` re-runs Next's matcher over the real route tree so a key that drifts either way fails before a build. `check:og-trace` still fails the build if a card loses sharp.
