## ADR-1684: A Walk, Run or Stretch keeps counting past its target and banks the whole run, and the reveal's fallback Dispatch names the activity just done (LIVE-674)

**Status:** Accepted · 2026-09-30 · backlog `LIVE-674` (closed here) · re-tested first per [ADR-1082](DECISIONS.md) · extends [ADR-443](DECISIONS.md) (Practice Depth: PD0-5, PD4, PD7) · keeps [ADR-627](DECISIONS.md) (the run-over gate) and [ADR-229](DECISIONS.md) (the cached daily Dispatch) · no migration

**Context.** LIVE-674 carried three loose ends from Practice Depth. Re-tested on `main` at `451c500f0`:

1. **Timed Movement did not auto-continue.** `components/on-air/movement-session.tsx` capped both finishes at `finishCap` (`Math.min(done, finishCap)`, the plan length or a resume's target), and past the end the live screen showed a dimmed `0:00` and "Done". A member who walked 18 minutes on a 10 minute walk banked 10, so the deeper time could never earn its tier, although ADR-443 says the tier is earned by how long the member actually practices and the Be Still sit already counts past its target (`+M:SS`, a live tier cue, the whole sit banked).
2. **The Vera fallback could name the wrong activity.** When both of the reveal's state reads fail, `completeSession` shows the cached daily Dispatch from `lib/vera-dispatch.ts`. That line is minted once per member per day and replayed after every session that day, and its AI voice (`voiceCopy`) was told only "after finishing a practice session", with nothing stopping it from writing "Good sit." into a line a later walk replays. The fallback also dropped the activity opener the primary path leads with. And the `depth_mark` template still said "hits 25 Deep", a retired name (docs/NAMING.md, ADR-305).
3. **The per-mode live walkthrough on a preview (PD7-2)** had not been done. It needs a signed-in member on a deployed preview, so no code can do it.

**Decision.**

1. **Auto-continue for the duration modes.** `lib/movement.ts` gains `AUTO_CONTINUE_MODES` (walk, run, stretch), `autoContinues(plan)`, `overtimeAt(plan, elapsed)` and `movementFinishSeconds(plan, { resumeOffset, bankedThis, finishCap })`, all pure. An auto-continue plan banks the earlier partial plus the whole of this session. Yoga (a pose sequence) and Strength (rounds) keep the plan-bounded cap, and Play still banks raw. This is the "duration-based Movement (walk/run/stretch)" scope named in IDEA-007 and the task inventory.
2. **The live screen matches the sit.** Past the target a Walk, Run or Stretch keeps its ring, the clock reads `+M:SS`, the line reads "Going deeper", and the tier cue sits under it. `liveDepthCue` moved from `components/on-air/session.tsx` to `lib/practices/tiers.ts`, beside `achievedTier`, and both timers call that one copy, so the cue names the tier the economy pays on. The end chime still rings once at the target.
3. **The run-over gate is unchanged and now matters.** The gate target is still the plan length (or the resume's remaining time), so at 150% the member is asked "Still moving?", and an unattended run finalizes at the last confirmed point. That clamp runs before `movementFinishSeconds`, so removing the cap does not let an abandoned walk bank hours. The over-deadline crash-recovery resume still finalizes at the target.
4. **The error-screen retry replays the same claim.** Movement's "Try again" recounted `Date.now() - startedAt`, which the cap used to hide. Uncapped, it would bank the time spent on the error screen. It now replays the exact seconds and options of the failed finish (`lastFinish`), as the sit's `lastFinishArgs` already does.
5. **The fallback names this session's activity.** `lib/on-air.ts` gains `fallbackSessionDispatch(kind, cached)`, which leads the cached line (or the steady template) with `dispatchOpener(kind)` for THIS session. `completeSession` builds its fallback with it. The activity is never written into the cache, because the cache replays across sessions.
6. **The cached line stays activity-neutral.** `cleanDispatchCopy(raw, fact)` (moved to the import-free leaf `lib/on-air/dispatch-copy.ts` and re-exported from `lib/vera-dispatch.ts`) rejects a voiced line that names an activity word (sit, walk, run, yoga, breathing, journal, stretch and their forms) that its fact does not, so the template stands. A Journey titled "Morning Walk" can still be named. The prompt says the same thing. `dispatchKindFor` checks `movementMode` against `MOVEMENT_MODES`, not a copied list. The `depth_mark` template now reads "reaches 25 logs".
7. **The walkthrough is recorded, not claimed.** The LIVE-674 CLOSED paragraph lists exactly what a human clicks on a preview for each mode and what each screen should read. This change does not say the walkthrough was done.

**Rejected.** Passing the activity into `getOrCreateDispatch` and its AI prompt, as PD0-5 first sketched. The line is cached for the day, so the first session's activity would replay after every later one, which is the bug this change fixes. Auto-continue for Yoga and Strength: past the last pose or round there is no structure left to follow, and ADR-443's amendment kept them bounded on purpose. Dropping the run-over gate for Movement past target: an unattended run would inflate airtime, which ADR-627 exists to stop.

**Consequences.** A 10 minute walk kept going to 18 minutes banks 18, so a walk that starts Standard can finish Heavy (15 minutes or more), as a sit already does. The server needed no change: `completeSession` already accepts up to four hours and `logPractice` pays `achievedTier` on the seconds it is sent. The reveal's fallback now reads "Nice walk. Same time tomorrow..." after a walk and "Good sit. ..." after a sit, from the same cached line. The Dispatch archive at /on-air/dispatches shows cached lines that name no activity the fact did not. The row's probe runs the pure functions in-process (walk, run, stretch, yoga, strength, the fallback opener per kind, the copy guard) and reads the component and action wiring. It fails on `main` at its first arm, and 19 of 19 arm mutations fail it.

**Rows.** `LIVE-674` (closed here).
