## ADR-1697: The /admin/qr check-in code previews are masked in the visual suite, and the per-second signing stays (LIVE-736)

**Status:** Accepted · 2026-09-30 · backlog `LIVE-736` (filed and closed here) · cause (e) of `LIVE-213`, named in #3109 · leaves LIVE-688's signing (ADR-1654) as it is · no product behaviour change

**Context.** The four `admin-qr` visual looks failed pr-compare on every run, with a different count on each retry. Two captures of the same tree about 30 minutes apart (runs 36667124353, 36676490803) agreed on 114 of 118 files and differed only there, in 96 x 96 bands over the check-in QR codes. LIVE-688 signs each node code over (node id, issued-at in unix seconds) and the page signs a fresh one on every render, so the modules change every second.

**Decision.** In `NodeCard` (`app/(main)/admin/qr/qr-studio.tsx`) the SVG is inlined by an `h-full w-full` square inside the fixed `w-28 h-28 p-1.5` white frame, and that square carries `data-visual-mask="qr-node-code"`, registered in `VISUAL_MASK_SITES` as a `live` site with its reason. The mask covers the code (98 px) and not the frame (112 px): on a phone the previews sit in the page's centre column, and LIVE-458's probe reads the tallest solid mask run down that column as the scans chart's 112 px box, so a frame-sized mask was measured in the chart's place. The four `admin-qr` baselines are recaptured on the runner with the mask in place. The frame, the rest of each card, and the page's unsigned QR previews stay in the picture.

**Rejected.** A stable issued-at per node, such as its creation time: the issued-at is the code's security meaning (a reprint issues a new one), and bending it for a screenshot trades a real property for a test one. Taking /admin/qr out of the blocking tier: a gate that goes advisory for one box gives up the whole page.

**Consequences.** A change to what a check-in code looks like is no longer caught by the /admin/qr pixel diff. Scannability and the node code are unit-tested in `lib/qr` (`scannability.test.ts`, `node-code.test.ts`), and the preview's box, label and actions are still photographed.
