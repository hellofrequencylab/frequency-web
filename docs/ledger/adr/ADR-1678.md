## ADR-1678: /practices is the one front door; /library is a permanent redirect to it, and the Library's ranked catalog lives there as a block (LIVE-681)

**Status:** Accepted · 2026-09-30 · backlog `LIVE-681` (closed here) · re-tested first per [ADR-1082](DECISIONS.md) · carries out the owner ruling recorded by HYG-138 ([ADR-1624](DECISIONS.md)) · amends [ADR-109](DECISIONS.md) (the Community Library surface) · no migration

**Context.** Practices and the Library were two front doors to overlapping things. `/practices` held the member's own practice blocks and the faceted practice library; `/library` held one ranked grid of practices AND journeys (the `community_library` RPC), a love rating that feeds that rank, a Create menu, and the door to the staff review queue. On 2026-09-29 the owner ruled "Merge into Practices": one front door, `/practices` holds the Library's resources and `/library` redirects to it, forwarding its query; the review queue keeps its own route; menus and the sitemap point at `/practices`. Re-tested on `main` at `30975a1b0`: both pages rendered, the member rail (`lib/nav-areas.ts`) and the footer (`lib/nav/registry.ts`) both offered Library, and no redirect existed.

**Decision.**

1. **One 308, exact.** `next.config.ts` carries `{ source: '/library', destination: '/practices', permanent: true }`. Permanent, because bookmarks and any operator `menu_items` row still naming `/library` cannot be rewritten from code. Next forwards the request query onto the destination, so `/library?type=journey` arrives as `/practices?type=journey`. The source is exact, with no `:path*` pair, because `/library/review` is the staff queue and keeps its route; `lib/marketing/redirect-shadow.test.ts` fails if a wildcard is added. `app/(main)/library/page.tsx`, its `loading.tsx` and its client `interactive.tsx` are deleted: a redirect is checked before the filesystem, so a page left behind would be dead code.
2. **The Library's catalog is a `/practices` block.** `practices-best-of` ("Best of the library") is a layout module in `LAYOUT_MODULES`, placed on `/practices` between the member's own practices and the faceted practice library. It is the Library's grid unchanged in substance: practices and journeys from `getLibrary` (featured first, then the RPC's rank), All / Practices / Journeys tabs, the time chip, adoptions, completions, score, and the love rating (`RateButton`, moved to `components/library/rate-button.tsx`; `rateContent` stays in `app/(main)/library/actions.ts` beside `reviewContent`). It reads its view from the `x-search` header like `practices-library` does, and its URL keys are the Library's own `type` plus a new `best=all`. It shows a 12-card preview and "Show all" opens the RPC's 200, so a full ranked list does not bury the practice library below it. Its links keep every other facet and land on the block's anchor. The URL half is pure (`components/widgets/practices/best-of-view.ts`) and tested.
3. **The review queue's door moves to `/practices`.** The page header shows "Review queue" to the people `canReviewLibrarySubmission` admits (staff or a granted Platform moderator), the same helper the queue page and the Approve action ask. The queue page's back links and its refusal redirect now go to `/practices`. Every write in `library/actions.ts` revalidates `/practices` instead of `/library`.
4. **No menu offers the old door.** The `library` row leaves `NAV_AREAS` and the footer's Quest group; `/library` leaves the menu editor's `KNOWN_ROUTES` and `CONTENT_EDIT_ROUTES` (there is no header left to edit). The `library` access-matrix surface and its `AREA_ICONS` glyph stay, because a stored override or an operator menu row may still name the key and the rail must not draw it bare. The sitemap and robots never listed `/library` (it was a member page), so there is nothing to remove there; `pnpm check:seo` is green.

**Capability ledger (nothing dropped silently).** The ranked practices-and-journeys list, the tabs, the love rating, the featured-first order and the review door are all on `/practices` now. The Library's Create menu offered Practice and Journey: `/practices` already has its own New Practice button, and journey creation lives at `/journeys` (its New Journey button), which the block's header links to. The Library's `?pillar=` filter never worked: `community_library` returns `pillar` as null for every row, so any value matched nothing. Forwarded, the same key now filters the faceted practice library by Pillar slug, which is what the link meant. The best-of block does not read it.

**Rejected.** Keeping `app/(main)/library/page.tsx` as a `permanentRedirect()` stub (a route file and a server render to do what the edge does for free, and the ADR-1199 rule is that a consolidation deletes what it replaced). A `/library/:path*` wildcard (takes out the review queue the ruling keeps). Moving the review queue under `/practices` (the ruling keeps its route; moving it is a separate change with its own redirects). Folding the journeys into the practice library's own query (`searchLibraryPractices` is practice-only and is shared with `/discover`). Rendering all 200 ranked cards by default (it would push the practice library a page down).

**Consequences.** A member on an old Library link lands on Practices, on the lane the link named. Staff reach the queue from the Practices header. A `page_content` row keyed `/library`, or an operator `menu_items` row pointing there, is no longer read or needed: the menu row rides the 308, and a sweep of production for the `/library` string (the ADR-1020 lesson) is operator housekeeping, not a code change. A practice filter change on `/practices` (the toolbar and the practice library build their own links) resets the best-of tab to All, which is the same page state a member gets on first arrival. `lib/library-door.test.ts` locks the rule, the kept review route, the lane parsing and link building, the block placement, the review door and the menu removals. The row's probe fails on `main` at the first arm.

**Rows.** `LIVE-681` (closed here). `OWN-054` stays done; its probe read the deleted `app/(main)/library/page.tsx` for the review-door gate, so that one arm now reads the same gate on `app/(main)/practices/page.tsx`, where the door lives.
