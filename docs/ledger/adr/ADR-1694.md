## ADR-1694: The visual baselines are retaken on a preview built after SUPPORT_CHAT was set for Preview, and what still keeps pr-compare red is two regressions on main, not the camera (LIVE-213)

**Status:** Accepted · 2026-09-30 · backlog `LIVE-213` (progress; stays open) · re-tested first per [ADR-1082](DECISIONS.md) · follows [ADR-1573](DECISIONS.md) (preview is canon), [ADR-1277](DECISIONS.md) (the masks) and [ADR-1525](DECISIONS.md) (the environment stamp) · no migration, no mask added or removed, no budget changed

**Context.** `pr-compare` (e2e.yml) last passed at 2026-09-29 04:26Z (run 36521639215) and has concluded failure or been superseded on every pull request since. The owner ruled preview is canon on 2026-09-29 and SUPPORT_CHAT was set for the Preview environment that day. Read from the job logs of run 36658607361 (LIVE-709, 2026-09-30) and from `pnpm visual:bands origin/main HEAD` over this branch's first recapture (run 36667124353, commit 4c5d82cb7), the red has five separate causes:

1. **The support chat now renders on previews (the row's own premise, class a).** Every public baseline differs by exactly 3,481 px in one band, a 59 x 59 box at the bottom right of the first screen: rows 724-782 x 1189-1247 at 1280 x 800, rows 768-826 x 314-372 at 390 x 844, rows 492-550 x 244-302 on the 320 x 568 header band. That is the support-chat button (56 px, `bottom-4 right-4`) under its `data-visual-mask` box. `supportChatFlagEnabled()` is read by three prerendered layouts, so the value lands at build time: every preview built after the value was set carries the widget, and the committed set, photographed on 2026-09-28 previews, does not. 84 of 118 captured files moved for this reason alone, with the 400 px budget untouched.
2. **Pages that changed on purpose since the last capture (class c, intended).** `/settings` is 533 to 811 px taller at every width; `/admin/content/practices` is 742 px taller (LIVE-643's needs-attention suggestions, #3032); the Space console's tabs read Home, Resonance, Marketing, Offerings & Money, Content & Programs and the phone footer carries Shop, Calendar, Your people and Menu; the desktop sidebar's Community group no longer lists Channels or My Contacts (cropped: rows 406-550 x 48-193 on every desktop shell file; it first failed at 2026-09-29 07:31Z, run 36537092351, with no commit to `main` touching the rail between 04:33Z and 07:31Z, so it reads as a saved menu or App setting rather than code, and the owner should confirm it is wanted). None of these is a camera fault; each is a page that moved since 2026-09-28.
3. **An accessibility regression from LIVE-643 (class c, real).** The smoke + a11y step fails `/admin/content/practices` at 40 serious+ `target-size` elements against a reading of 0, desktop and mobile: every row now puts `PracticePlacementButton` (19.1 px) beside the existing View link (`ExternalLink h-3 w-3`, 12.8 px) in `app/(main)/admin/content/practices/practices-table.tsx`, so neither has 24 px of clear space.
4. **LIVE-713's scanner spec fails on a protected preview (class c/d).** `test/e2e/scan-camera.spec.ts` fails twice: `/scan is served camera=(self) ... one header each` receives zero `Permissions-Policy` lines for `/scan` with `maxRedirects: 0`, and the soft-navigation case never shows the viewfinder. The first is most likely the harness, not the header: `playwright.config.ts` sends `x-vercel-set-bypass-cookie: true`, and the first bypassed request to a protected preview answers with Vercel's own cookie-setting redirect, which carries none of the app's headers.

5. **LIVE-688 made `/admin/qr` differ on every render (class c, live).** Two captures about 30 minutes apart (runs 36667124353 and 36676490803, the second after merging main, whose new commits touch no captured pixel) agree to the pixel on 114 of 118 files and differ only on the four `admin-qr` files, by 9,434 to 17,021 px in 96 x 96 bands: the check-in QR codes themselves. Since #3065 (LIVE-688) every node code signs `(node, issued-at)` with `issued-at` in seconds (`lib/qr/node-code.ts`, `signNodeCode(nodeId, Date.now())`), so the studio draws a different code each request and no baseline can hold it.

Nothing in the five is infrastructure in the sense the row feared: the preview URL resolved, the session minted, the operator floor held, and the environment stamp agreed (preview on both sides).

**Decision.**

1. **Recapture the whole committed set through the documented path**: `e2e-manual.yml` with `update_baselines` and `capture_shell`, pointed at this branch's own preview, with `main` merged first, so the set is photographed on a preview that carries the widget. The stamp stays `preview`. The runner commits the PNGs; nothing is photographed in a sandbox.
2. **No mask and no budget move.** The support-chat mask stays exactly as it was; only its registered reason, the component comment, `test/e2e/capture-env.ts` and `test/e2e/README.md` stop saying "Production and not Preview" and say since when both carry it.
3. **LIVE-213 does not close here.** Its closing reading is a green `pr-compare`, and causes 3, 4 and 5 are regressions on `main` from other rows that no recapture can clear. They are handed back with a precise fix each rather than folded into this change (one row per pull request).

**Rejected.** Masking the practices table or skipping the scanner spec to get a green run (the row forbids a new mask, and a skip would hide two real failures). Recapturing the a11y counts (`update_a11y` refuses a rise by design, and the rise is real). Removing the support-chat mask on the strength of "pr-compare needs no masks" (a separate decision the ruling does not require; the mask is harmless now that both environments carry the box).

**Consequences.** Once this lands, a pull request's `pr-compare` visual tiers judge its own change again instead of failing 84 public files and 34 shell files for `main`'s reasons. The run stays red on the smoke + a11y step and on the four `admin-qr` files until the three regressions are fixed: give the practices table's View link and placement button a 24 px box (for example `inline-flex h-6 w-6 items-center justify-center`), then recapture the four `admin-content-practices` PNGs; and let the scanner spec read the app's response rather than Vercel's bypass redirect (request each path once to set the cookie, or follow a same-URL redirect before asserting), then re-read the soft-navigation case on a preview; and make the studio's QR deterministic per node (sign it with a stable issued-at the page can reproduce, such as the node's creation time, or register the QR image as a LIVE mask site under LIVE-688's own row, which is that row's decision, not this one's). The next green `pr-compare` after all three closes LIVE-213.

**Rows.** `LIVE-213` (progress, stays open).
