## ADR-1668: check:id-collisions reads the other open PRs through git, so a run costs one REST call and a busy hour no longer empties the token's quota (HYG-150)

**Status:** Accepted · 2026-09-29 · backlog `HYG-150` (filed and closed here) · re-tested first per [ADR-1082](DECISIONS.md) · amends [ADR-1509](DECISIONS.md) (the gate) and [ADR-1603](DECISIONS.md) (its retry budget) · no migration

**Context.** On 2026-09-29 at 22:30Z the required `checks` job on #3079 went red for one reason: the cross-PR arm of `check:id-collisions` got `GET pulls (page 1): HTTP 403` with `x-ratelimit-remaining: 0` and `x-ratelimit-resource: core` (job 109645795505). That is the primary hourly quota of the repository `GITHUB_TOKEN` (1,000 requests an hour), with a reset 22 minutes out, so the five-minute retry budget from ADR-1603 could not outlast it and the gate correctly failed. Re-tested on `main` at `a5bb99b01`: every run spent one pulls listing, then one `listPullRequestFiles` call per other open PR, then a contents download for each watched file a PR touched. With about twenty open PRs that is 21 or more requests a run, and every push and update-branch paid it again. The owner's ruling: change the rule so this stops jamming PRs. The gate's own rule stays: a gate that answers clean when it could not look is the failure it exists to prevent, so skipping on a limit is not an option.

**Decision.**

1. **One REST call on the normal path.** The pulls listing (numbers, head shas, creation times) is the only REST read that stays. Git does not spend REST quota.
2. **The other PRs' heads come through one git fetch.** `git fetch --depth=1 --filter=blob:none origin +refs/pull/<n>/head:refs/id-collisions/pr/<n>` for every other open PR at once, into a private ref namespace, so no branch or remote ref moves. Measured on a depth-1 checkout of `main`: 21 heads in 1.0 s and a 133 KB pack, with `main`'s deepened history (what `check:shipped-ids` walks) unchanged at 845 commits. If the one fetch fails (one missing ref fails the whole fetch), each head is fetched alone, so one bad ref costs one PR.
3. **Ids come from the tree, not the diff.** A fragment's id is its file name, so `git ls-tree -r --name-only <head> -- docs/ledger` gives them with trees alone. The two legacy files are read with `git cat-file` only when their blob id at the head differs from the base tip's, and once per distinct blob, because stale PRs share their merge base's blob. The base tip's ids are subtracted exactly as before, so a stale head introduces nothing.
4. **Fallback, then red.** A PR whose head git cannot fetch or read goes through the pre-HYG-150 REST path (files listing, then contents) for that PR alone. When that cannot answer either, the run throws and the job is red, as it always was. The log says how many PRs were read through git and how many through REST, and why each fallback happened.
5. **A git seam.** Every git call in the script goes through one injectable function (`runGit`), so `scripts/check-id-collisions.test.ts` drives the fetch, the tree reads, the blob cache, the per-PR fallback and the double failure with a fake and never touches the network or the repo's refs. `.github/workflows/ci.yml` needed no permission change: the fetch uses the checkout's own `contents: read` credential, and `pull-requests: read` stays for the listing. Its comments now say git.

**Rejected.** Treating a 403 as a skip (the gate would answer clean when it could not look). A longer retry budget (a primary quota resets on the hour, not in minutes, and a 20-minute job cannot wait it out). A separate token with more quota (an owner secret for a problem the volume causes). Fetching `refs/pull/*/head` in a workflow step (every PR ever opened, thousands of refs). Reading the legacy files through the head's merge ref to see only the PR's own diff (conflicting PRs have no merge ref, and after fragments the legacy files rarely change).

**Consequences.** A run's REST cost drops from 1 + N files listings plus downloads to 1, whatever N is, so twenty PRs pushing in the same hour cost twenty requests rather than four hundred or more. After a change to `docs/DECISIONS.md` or `docs/BUILD-BACKLOG.json` on `main`, stale PRs' legacy blobs differ from the base tip's and are read through git: about 2 MB compressed per distinct blob, shared across every PR on that blob, and still no REST call. The gate's verdicts are unchanged: the same ids, the same later-opened-renumbers rule, the same never-skip contract. The row's probe runs the real `main()` with an injected git seam and a counting fetch and fails on `main` (8 REST calls for three other PRs).

**Rows.** `HYG-150` (filed and closed here).
