## ADR-1653: The five adoption classes that parallel merges raised go back under their baselines by using the kit, not by raising them (HYG-149)

**Status:** Accepted · 2026-09-29 · backlog `HYG-149` (closed here) · no migration · no baseline raised

**Context.** `node scripts/check-adoption.mjs` failed on main at 8b0b1909e. Five classes were above their frozen baselines: literal-radius 2156 to 2165, subtle-tiny-type 0 to 1, raw-button-bg 403 to 405, literal-display-type 48 to 50, raw-input 88 to 91. Each PR that added a site passed the ratchet alone. Merged together, the counts rose. The step is advisory in `ci.yml`, so nothing stopped the merges, and the nightly maintenance run reports it on main.

The sites were found by counting each class with the script's own `countEntry` at the commit that froze the baseline and at main, file by file:

- literal-radius +9: `practice-placement.tsx` +4, `loom-grid.tsx` +2, `curate-with-vera.tsx` +2, `delete-account.tsx` +1.
- raw-button-bg +2: the Fill with Vera chip (`curate-with-vera.tsx`, `hover:bg-primary/10`) and the Remix dialog (`remix-practice-button.tsx`).
- raw-input +3: the carrier and tracking inputs in `order-fulfilment-control.tsx`, and the Straighten slider in `loom-crop-editor.tsx`.
- subtle-tiny-type +1: the unsized-images note in `space-loom-studio.tsx`.
- literal-display-type +2: the Circles block and the Contact form block headers (2026-09-24), both copies of the Events block header's `sm:text-3xl`.

**Decision.**

1. **Fix the sites with the kit. Do not raise a baseline.** `rounded-lg` becomes `rounded-control` and `rounded-2xl` becomes `rounded-card` (the same pixels at the base theme). The one `rounded-md` icon button and the one `rounded-xl` panel take the control and card roles.
2. **Buttons compose `Button`.** Fill with Vera is `Button variant="primarySoft" size="sm"`. In the Remix dialog, the Remix it confirm is a plain `Button` (primary, md), the near-miss conversion ADR-1119 describes. The direction chips keep their selected tint.
3. **Inputs compose the field kit.** The fulfilment inputs are `Input` from `components/ui/field`. The Straighten slider is `RangeField` from `components/admin/range-field`, which KIT.md names for a labelled slider with a readout.
4. **Tiny text is not subtle.** The note moves from `text-subtle` to `text-muted`, the AA pair at `text-2xs`.
5. **The three Space-profile block headers share one role.** Events, Circles and Contact move from `sm:text-3xl` to `sm:text-display-h3` together, so the sibling headers on one Space page stay the same size. Events was already under the baseline; converting it too keeps the three consistent and retires one more site.

**Consequences.** `check:adoption` exits 0 with no `--allow-raise`. literal-radius reads 2155 and literal-display-type 47, one under each baseline. These are not banked with `--update`, so a parallel PR that adds one site in either class still passes. Pixel moves are the swaps themselves: converted buttons gain the primitive's `tap-target` and `press`, the Straighten label takes RangeField's meta style, and the three block headers follow the display-h3 clamp (28px to 36px) instead of a fixed 30px from `sm` up.
