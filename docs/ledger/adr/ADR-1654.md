## ADR-1654: Node codes carry an HMAC over (node, issued-at), and printed codes from before get until 2026-12-01 (LIVE-688)

**Status:** Accepted · 2026-09-29 · backlog `LIVE-688` (closed here) · amends ADR-115 (the per-code "Require a signed code" toggle is retired) · no migration, no new env var

**Context.** A Space check-in and every `/admin/qr` code is a `nodes` row, and a scan is `/n/<nodeId>?s=<value>`. `verifyCapture` compared `?s=` to a stored random `nodes.secret` with `!==`, and only when the node had one. Check-in nodes were minted with a secret. Admin codes had one only when an operator ticked "Require a signed code", so an unticked code checked a member in from its node id alone, and the `/admin/qr` actions file still said "Signed payloads remain a follow-up". Re-tested on this tree before the change: that line was present, and the verifier had no HMAC.

**Decision.**

1. **One signed code for every node.** `lib/qr/node-code.ts` issues `v1.<issued-at base36>.<tag>`, where the tag is the first 16 bytes of HMAC-SHA256 over `node-code:v1:<nodeId>:<issued-at>`. Every surface that renders, downloads or prints a node code (`/admin/qr`, `/api/qr?node=`, `/print/qr?node=`, a Space's check-in settings) builds its URL with `signedNodeUrl`, so none of them can print an unsigned one.
2. **The key is one the deploy already has.** `signingSecret('node-code', ['UNSUBSCRIBE_SECRET'])`, domain-separated by the `node-code:` prefix so a node code never verifies as any other token signed with that key. In production a missing key throws: a code will not render, and verification refuses every signed code (fail closed). No new env var.
3. **The verifier refuses a forged or tampered code.** `verifyCapture` asks `nodeCodeVerdict`. A value shaped like a signed code must verify for this node, whatever the date: a tag for another node, an edited tag or issue time, or an issue time more than 5 minutes ahead all return `bad_signature`, and a tampered signed code never falls back to the legacy path. The compare is constant-time.
4. **Printed codes from before this ship get a grace window, until 2026-12-01 00:00 UTC** (`LEGACY_NODE_CODE_GRACE_ENDS`, three weeks before launch day). Until then a pre-signing code still claims: a bare `/n/<id>` on a node that never had a secret, or the node's old random secret (exact match). Each such claim logs `[node-code] pre-signing code accepted inside the grace window; reprint it` with the node id, so the runtime logs list the codes that still need a reprint. From 2026-12-01 those scans fail with "Couldn't verify this code."
5. **The toggle is retired, the column is kept.** Signing is no longer a per-code option, so the "Require a signed code" checkbox and its badge leave `/admin/qr`, and neither the studio nor `ensureCheckinNode` mints a `secret` any more. Existing `nodes.secret` values are left untouched because they are what keeps old printed codes working through the grace window. Dropping the column is a later cleanup once the window has closed.

**Migration path for codes already printed.** Nothing breaks today. Before 2026-12-01, open the code in `/admin/qr` (or the Space's check-in settings) and download or print it again; the new file carries a signed code. Watch the `[node-code]` log line to see which printed codes are still being scanned. After 2026-12-01 an old print shows "Couldn't verify this code" and the fix is the same reprint. The node id, its capture history and its settings do not change.

**Rejected.** A new `NODE_CODE_SECRET` env var (rotation independence, at the cost of a deploy step and a new fail-closed dependency; the brief asks for a key the code already has). A short expiry on signed codes (a printed code has to outlive the print run; issued-at is carried so a later per-node "codes issued before X are void" can be added without a reprint format change). Hashing the stored secret instead (still a per-node plaintext credential, and still optional per code). Refusing old prints immediately (Spaces would find their door code dead at the next event with no notice).

**Consequences.** A code built from a node id, or edited, or copied from one node onto another, no longer checks anyone in. A photographed or copied code still claims, as any static printed code does; the geofence (`proximity_m`) is the defence for that and is unchanged. Rotating `UNSUBSCRIBE_SECRET` voids every printed node code, so a rotation now needs a reprint pass. The QR image in `/admin/qr` changes on each render (its issued-at is the render time); every version verifies.

**Rows.** `LIVE-688` closed here. Tests: `lib/qr/node-code.test.ts` (round trip, forgery, grace, fail closed) and `lib/engagement/verify.test.ts` (the verifier returns `bad_signature` for a cross-node or tampered code and, after the window, for a bare id or the old secret).
