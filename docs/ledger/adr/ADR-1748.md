## ADR-1748: The default Space site theme is labelled Default, and "Frequency" names the platform's design system

**Status:** Accepted · 2026-10-13 · backlog `LIVE-919` · owner-ruled · amends [ADR-1726](DECISIONS.md) (the theme's label, not its id)

**Context.** The owner is building a second design system for the main platform, beside DAWN, and named it Frequency. "Frequency" already labelled two other things: the default Space site theme (`SITE_THEMES`, lib/theme/site-style.ts) and the font set it wears (`SPACE_THEMES`, lib/theme/space-themes.ts), both from ADR-1726. Three things under one name, two of them in the same owner's picker, is the collision NAMING.md exists to stop. The owner ruled on 2026-10-13: "Change the name of the default Frequency theme to Default. The new theme will be match the Frequency theme styles."

**Decision.** (1) The site theme and the font set with id `frequency` are labelled **Default** in every picker, in the website editor and in the help article. (2) The ids stay `frequency`: they are the values every saved `preferences.siteStyle.theme`, `preferences.theme` and page-theme entry holds, and renaming them is a data migration for no reader's benefit (NAMING.md, persisted identifiers). (3) "Frequency" as a theme name now means the platform design system the owner is building beside DAWN; its own decision record comes with it.

**Rejected.** Renaming the stored id (a migration across every Space's preferences, and a stored `frequency` would then need a read alias anyway). Another descriptive label such as "House" (the owner chose Default, and "house theme" is already barred in copy by NAMING.md).

**Consequences.** `scripts/probes/default-site-theme-label.mjs` holds the labels for LIVE-919. Code comments that say "the Frequency theme" for the Space look are history from ADR-1726 and read with this ADR.
