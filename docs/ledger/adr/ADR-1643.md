## ADR-1643: A native client calls a versioned /api/v1 with a Supabase bearer token, and lands on the same caller the web resolves (LIVE-715)

**Status:** Accepted · 2026-09-29 · backlog `LIVE-715` (closed here) · filed by `HYG-146` from the owner's mobile ruling (2026-09-29 ~20:10Z: "everything done and fully wired for an iOS launch, but I don't want to build the app yet"; stack Expo / React Native) · re-tested first per [ADR-1082](DECISIONS.md) · takes Open decision 3 of `docs/CAPABILITIES-AND-MOBILE.md` · restores the contract layer [ADR-018](DECISIONS.md) accepted and HYG-067 found deleted · no migration · numbered 1643 by the orchestrator's reservation

**Context.** Re-tested on `main` at `bc1913405` on 2026-09-29 from the repo. There is no `app/api/v1`, no `lib/contract/` (built and removed twice as a zero-importer orphan: `views.ts` 2026-06-06, `types.ts` 2026-06-14), and no route handler reads a Supabase bearer token: `lib/supabase/server.ts` reads cookies only, and the only `Authorization` header any `app/api` route reads is the cron secret. The web's writes are `'use server'` actions, which a native app cannot invoke. The proxy runs on every `/api` path, so a cookieless native request would have been given first-touch attribution and marker cookies on its JSON. Every other app-readiness row (`LIVE-716` to `LIVE-726`) needs this seam first.

**Decision.**

1. **One versioned namespace, one envelope.** `/api/v1/*` route handlers. Every body is `{ data, error }` with exactly one non-null; errors carry a stable `code` from a fixed table (`unauthorized` 401, `profile_required` 403, `forbidden` 403, `not_found` 404, `invalid_input` 400, `conflict` 409, `rate_limited` 429, `update_required` 426 for `LIVE-722`, `internal` 500). Every response sends `Frequency-Contract: 1`, `Cache-Control: no-store, private` and `Vary: Authorization, Cookie`. Routes answer only through `ok` / `fail` in `lib/contract/respond.ts`.
2. **Bearer or cookie, one caller.** `lib/contract/caller.ts` `authorizeCaller` accepts `Authorization: Bearer <supabase access token>`, verified by Supabase Auth (`auth.getUser(token)` on `lib/supabase/bearer.ts`, the anon key plus the token, never the service role), and reads the caller's own profile row with that token under RLS. With no `Authorization` header it uses the web cookie through `getCallerProfile()`. Both build the caller through `callerFromViewerRow`, extracted from `lib/auth.ts` `resolveCaller` without changing it, so a bearer caller and a cookie caller for the same row get the same `CallerProfile`. No new auth system.
3. **The rules that are easy to get wrong.** A present `Authorization` header decides: a bad token is `401` even beside a valid cookie. An Auth outage (a retryable fetch error or a 5xx) is `internal`, never `unauthorized`, because an app signs out on 401. A signed-in account with no profile is `profile_required`. View-as (a web cookie) never applies to a bearer caller. A cookie-session write needs an `Origin` matching the host (the CSRF check route handlers never had); a bearer write does not.
4. **The proxy leaves `/api/v1` alone.** The matcher's lookahead excludes `api/v1(?:/|$)`: no marker cookies, no first-touch record, no redirects. A web cookie session is read and refreshed by the route's own server client. The prefetch fuse (`LIVE-649`) only touches requests carrying `next-router-prefetch`, which an app never sends.
5. **CORS stays closed.** A native app needs none and the web is same-origin; opening it would only let other sites read a member's answers.
6. **Rate limit before credentials.** `rateLimited` runs first, through `lib/rate-limit.ts`, 300 a minute per address per endpoint (phones share carrier addresses), `whenUnconfigured: 'allow'` because denying would switch off the whole app at once. A forged-token stream cannot buy an Auth round trip each.
7. **`lib/contract/index.ts` is the shared file and imports `zod` only**, so the Expo app can compile against it. Input parsing goes through the repo's `parseInput` (`readInput` maps its throw to `invalid_input`). Every module in `lib/contract/` has a live importer (`app/api/v1/me/route.ts`), so an orphan sweep cannot delete it a third time.
8. **`GET /api/v1/me` is the worked example**: the caller's id, handle, display name, avatar, community role and level, staff role, tier, and which credential answered. Capabilities are not in it: `load-capabilities.ts` resolves the viewer from the cookie, so projecting them to a bearer caller is `LIVE-717`'s change, not a side effect here.
9. **Versioning.** Additive within v1. A breaking change is `/api/v2` beside v1, and a v1 route retires only after the minimum supported app version (`LIVE-722`) passes every build that calls it, recorded in an ADR. `docs/APP-CONTRACT.md` is the prose.

**Rejected.** A separate BFF service or tRPC/GraphQL (a second deploy and a second auth story for a transport a route handler already is). Verifying the JWT locally with the project secret (the owner asked for `getUser`, and a local decode cannot see a revoked session). Excluding `/api/v1` inside `proxy()` instead of the matcher (the proxy would still run its `getUser` round trip per request). A cookie fallback when the bearer token fails (a request would authenticate as someone other than the credential it names). Opening CORS "for later" (nothing needs it).

**Consequences.** A holder of a Supabase access token can call `GET /api/v1/me` and gets the same identity the web renders. The web is unchanged: `getCallerProfile` returns the same object through the same code, and every existing route keeps the proxy. Nothing new is reachable from `components/layout/app-shell.tsx`, and no dependency was added. Tests: `lib/contract/caller.test.ts` (bearer accepted, forged, expired, revoked, deleted user, malformed header, no fallback to a cookie, outage as internal, no profile, cookie still works, CSRF on a cookie write only, view-as on the cookie path only, and the bearer caller deep-equal to `getCallerProfile()` for the same row), `lib/contract/contract.test.ts` (the envelope, every code's status and headers, no CORS header, `readInput`, the types module importing zod only, the proxy matcher skipping `/api/v1` and nothing else), `app/api/v1/me/route.test.ts` (end to end, every body parsed with `meResponse`).
