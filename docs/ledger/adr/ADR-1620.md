## ADR-1620: An upload preview's src passes a whole-string allowlist that CodeQL can read, so its xss-through-dom alerts close in code instead of being dismissed

**Status:** Accepted · 2026-09-29 · backlog `HYG-137` (filed and closed here) · answers the owner ruling of 2026-09-29 on the CodeQL alert at `lib/onboarding/step-registry.tsx:109` ("Investigate and fix") · reverses the "dismiss, and leave the query armed" advice `lib/safe-image-src.ts` carried since the upload-preview helper landed · numbered 1620 by the orchestrator's assignment

**Context.** CodeQL's `js/xss-through-dom` ("DOM text reinterpreted as HTML", high) reports the onboarding avatar preview: `<input type="file">` `.files` flows through `URL.createObjectURL` (a taint step the query adds) and React state into `<img src={safe}>`, where `safe = safeUploadPreviewSrc(url)`. The same path is reported for `app/onboarding/form.tsx`, the feed composer and the report dialog. Investigated before changing anything. (1) No script runs here: an `<img>` does not execute a `javascript:` URL, an SVG loaded through `<img>` runs no script, React sets `src` as an attribute value (escaped on the server, `setAttribute` in the browser), and the only values that reach these sinks are a browser-minted `blob:<origin>/<uuid>` or the https URL the upload returned. (2) The helper was still weaker than its comment claimed. It ended in a prefix test, `/^(?:blob:|https?:)/`, on the URL parser's output, and the parser does not escape a blob: URL's opaque path, so `blob:https://app.local/"><img src=x onerror=alert(1)>` and a blob id with a quote or a space came back verbatim; so did credentials in an https URL. (3) CodeQL models no URL-scheme check as a barrier for this query. The barrier it does model for every taint configuration is a regexp test that is anchored at both ends and has no wildcard term (no `.`, no negated class, no `\S`/`\W`/`\D`), which sanitizes the tested value in the true branch. Measured with CodeQL 2.27.1 on the helper, the step registry and the upload-preview callers: the query reports all four sinks before the change and none after, and the full `security-and-quality` suite (the one CI runs) reports nothing new on those files.

**Decision.**

1. **`safeUploadPreviewSrc` ends in a whole-string allowlist.** After `safeImageSrc` parses and serialises the value, it is returned only if it matches one of two fully anchored, wildcard-free regexps: `blob:http(s)://<host>[:port]/<letters, digits, hyphens>` (what `createObjectURL` writes), or `http(s)://<host>[:port]/<path>[?query]` over an explicit character list (no credentials, no fragment, no quote, angle bracket, backtick, space or backslash, all of which the parser has already percent-encoded where it can). Anything else is null, and every caller already renders initials or nothing for null.
2. **A URL sanitizer in this repo ends in a test CodeQL can see.** A value handed to a URL sink returns only from inside `if (ANCHORED_ALLOWLIST.test(value)) return value`. Parsing and scheme checks stay for correctness, but they are not the last step. The HYG-137 probe holds `safeUploadPreviewSrc` to this shape: every non-null return guarded by such a test, each pattern anchored at both ends with no bare dot or negated class.
3. **An upload-preview alert is fixed, never dismissed.** If `js/xss-through-dom` reports an upload preview again, either a sink bypasses `safeUploadPreviewSrc` or a pattern was loosened. Fix that. Inline `codeql[...]` comments are not honoured by GitHub code scanning, and excluding the query repo-wide would hide a real `innerHTML` finding.

**Rejected.** Dismissing the alert in the Security tab (the owner ruled "fix", and a dismissal leaves the helper returning markup for a crafted blob id). `encodeURI` as the barrier (CodeQL would accept it, but it double-encodes a `%` the parser already wrote and does not refuse a scheme, so it would be a sanitizer for the tool rather than for the value). A host allowlist of known upload hosts (the preview hosts differ by caller and environment, a local Supabase is `http://127.0.0.1`, and a remote `<img>` host is a privacy question, not an XSS one; it can be added later without changing this shape). Widening `safeImageSrc` the same way in this change (its data: and same-origin shapes need their own patterns, and no alert names it).

**Consequences.** The onboarding step-registry alert and the three sibling alerts close on the next scan of `main`. A preview whose URL carries a fragment, credentials or an apostrophe renders no preview; none of the seven callers produce one. `lib/safe-image-src.test.ts` pins the hostile inputs (javascript:, vbscript:, data:text/html, SVG, protocol-relative, backslash, a blob id with markup or a quote) and asserts nothing returned can end or open an attribute.

**Rows.** `HYG-137` (filed and closed here).
