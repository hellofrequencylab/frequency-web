## ADR-1788: Check in returns to the Space Manage menu as a row that opens the existing panel (LIVE-949)

**Status:** Accepted · 2026-10-20 · backlog `LIVE-949` · builds on [ADR-1787](#adr-1787)

**Context.** LIVE-226 retired the `space.checkin` menu row and its function key because it duplicated an event mechanic, but the `?panel=checkin` workspace stayed and became the home of the door code, the NFC link and Regulars. With the row gone, no tab led to it: an owner setting up a tag could not find it.

**Decision.** One new row, `space.regulars`, labelled "Check in", sits in the Offerings and money box under an "At the door" group. It opens the same inline panel through `MODULE_PANEL_ID`. The retired id stays retired and its pin in `space-modules.test.ts` is unchanged; only the enumerated child and count pins grew by one.

**Rejected.** Reviving `space.checkin` (it would contradict the LIVE-226 pin and its function-key retirement). A second panel (the existing one already holds everything).

**Consequences.** No migration. The row is ungated, like Get paid, so it cannot hide the way a switch would.
