## ADR-1669: The capture turnstile spends about 250 API requests an hour for a ten-deep queue instead of ~14,400, waits out a spent quota, and a refused API read can no longer become the preview URL Playwright runs against (HYG-151)

**Status:** Accepted · 2026-09-29 · backlog `HYG-151` (filed and closed here) · amends [ADR-1331](DECISIONS.md) (the turnstile's look cadence and a sixth rule) without changing its one-capture-at-a-time rule or [ADR-1328](DECISIONS.md)'s lane · re-tested first per [ADR-1082](DECISIONS.md) · numbered 1669 by the orchestrator's assignment · no migration

**Context.** On 2026-09-29 the repository's `GITHUB_TOKEN` core quota (1,000 requests an hour per repository) read 0 twice in two hours (`x-ratelimit-reset` 22:52Z and 23:52Z), and about eight PRs' checks went red on API refusals. HYG-150 (#3084) removes `check:id-collisions`' per-PR cost; the larger consumer was `.github/workflows/e2e.yml`.

Re-tested on `main` at `645681934` and against the run itself:

1. **The turnstile's cost.** Every look made one paginated `listWorkflowRuns` per lane file (`e2e.yml`, `e2e-manual.yml`) plus one `listJobsForWorkflowRun` for **every** other in-progress run, every 30 s, in every waiting job, and six byte-identical copies share that script (two in `e2e.yml`, four in `e2e-manual.yml`). Run under a fake Octokit, main's script spends **12 requests on one look** behind a capture plus nine waiters. Ten waiters: 10 × 12 × 120 looks an hour = **~14,400 requests an hour**, the whole quota in about four minutes. A refused look is caught as "the Actions API (unreadable)" and polled again 30 s later, so the lane kept the quota at zero until each reset.
2. **The swallowed refusal.** The preview resolver ended every `gh api` read in `|| true`, and `gh api` prints the error **body** to stdout. #3066's `pr-compare` (run 36636201158, job 109638485701, head `36378cc5`) held its turnstile for exactly the 90-minute bound (21:58:01Z to 23:28:01Z, inside the spent hour), then resolved in under a second and ran every suite with `PW_BASE_URL: {"message":"Not Found","documentation_url":"https://docs.github.com/rest","status":"404"}` (read from the job log's step env): the refused deployments read was word-split into "deployment ids", each statuses read 404'd, and the 404 body became the URL. Playwright failed the smoke, public and shell tiers with "Cannot navigate to invalid URL", which reads as this PR's regression. The row's premise said "an EMPTY base URL"; the measured value was worse (an error body), and an empty one would have been worse again (every spec skips itself, a green that tested nothing). Replaying the refusal against main's resolver with a fake `gh` reproduces the exact value.

**Decision.** The smallest change that makes both consequences false; ADR-1331's lane, its peers, rule 3's ordering and rule 5's 90-minute ceiling are unchanged, and nothing that was a required check becomes skip-to-green.

1. **One runs read a look.** `listWorkflowRunsForRepo(status: in_progress)`, filtered to the lane files by the run's `path` (a run with no `path` is read, not guessed away). Replaces one read per lane file.
2. **Jobs read oldest first, stopping at the first run ahead.** One run ahead is enough to wait, so a typical look is 1 runs read + 1 jobs read. Newer runs seen waiting on two looks are not read again: rule 3 holds them behind this job while it waits. A newer run already capturing is still read and still waited for.
3. **The gap between looks stretches with the queue.** `TURNSTILE_POLL_SECONDS` 30 → **120**, multiplied by the number of older lane runs still in progress, capped at **3**: next in line looks every 2 min, third and later every 6 min. A job with three or more older runs is at least two captures (~30 min) from its turn, so 6 min between looks costs it nothing; the head of the queue pays at most ~1 min average extra per handoff. The count can overstate (an older run whose lane job is done but whose other job runs), which costs latency, never a second capture.
4. **Rule 6: a spent quota is waited out.** A 403/429 carrying `retry-after`, or `x-ratelimit-remaining: 0` with `x-ratelimit-reset`, sleeps until the reset + 5 s, never past the 90-minute bound (rule 5 still proceeds on time).
5. **The resolver tells "refused" from "none".** Every read goes through `read_api`, which prints nothing on failure and records why. A refusal checks `/rate_limit` (which costs no quota): a quota back inside the step's existing 12-minute window is slept out; one that is not fails the job at once with the reset time in the log and job summary; any other refusal retries on the normal 20 s cadence, and a last look that was refused fails rather than falling into "no deployment". A refused read in the pending classification fails too, instead of reaching the quiet green. A resolved value that is not an `https://` URL fails the step.
6. **Playwright refuses to start without a usable base.** `playwright.config.ts` exports `refuseUnusableBaseUrl`: a non-empty `PW_BASE_URL` that is not an http(s) URL throws anywhere, and an empty one throws on GitHub Actions (where it came from an empty step output). Locally, unset or empty still means "skip". The lighthouse step refuses a non-URL `PREVIEW_URL` before it audits. The guard lives in the config rather than in each step's `run:` so the four suite steps keep their single-command shape, which `visual-tiers.test.ts`, `shell-coverage.test.ts` and done probes read.

**The arithmetic (ten waiting `pr-compare` jobs behind one capture, as the new test computes it).** Before: 12 requests a look × 120 looks an hour × 10 = **~14,400/h**. After: 2 requests a look; the waiter with k older runs looks 30 / min(k, 3) times an hour, so 60 + 30 + 8 × 20 = **250/h**, a 57× cut. A ten-deep lighthouse lane costs the same again at worst, so both lanes full is ~500/h, half the quota, where one lane used to be fourteen times it.

**Rejected.** Dropping the turnstile or reverting to a job-level `concurrency` group (ADR-1328/1331: a group cancels the older pending job). A flat 6-minute look for everyone (the head of the queue would idle up to 6 min per handoff). Treating a refused read as "no deployment" or skipping the job on it (a skip-to-green of a job that tested nothing, the vacuous pass `preflight` exists to prevent). Waiting past the step's 12-minute window for a reset up to an hour away (the job's timeout is the capture's budget plus the turnstile's bound; the resolver was never given more). A `gh api -i` header parse in bash (`/rate_limit` answers the same question for free).

**Consequences.** A spent quota now reads as "GitHub API refused the preview lookup, quota spent until HH:MM:SSZ" on the job that met it, not as failed @visual tests. The turnstile's cost scales with nothing but the number of waiters, at 20 to 60 requests an hour each. `scripts/e2e-preview-gate.test.ts` runs the resolver under bash with a fake `gh` (ten arms, including the #3066 replay) and the turnstile under a fake Octokit and clock (nine arms, including the per-look cost, the stretch, rule 6 and rule 5), and every arm was watched go red against main's workflow and against a targeted mutation. The row's probe replays #3066, prices one look, prices a refused look, and asks Playwright's config to start on an error body.

**Rows.** `HYG-151` (filed and closed here).
