## ADR-1739: The Theme Element Library contract: tokens feed elements, every theme ships a manifest, infographics are data plus a layout, and every figure is truthful by construction

**Status:** Accepted · 2026-10-13 · owner-directed · extends [ADR-1727](DECISIONS.md) (one render path) and [ADR-1737](DECISIONS.md) (the design switch) · builds docs/EDITOR-ARCHITECTURE.md E1 (`defineBlock`) and E6 (presets-first inserter) · design input from Claude Design (the "Theme Element Library" handoff, 2026-10-13); its element package is still being drawn

**Context.** The owner asked for a design asset library in the website builder: every theme exposes all the elements of its style system, and an owner can easily add an element, a function, a pre-built block or a theme element, starting with an Infographic Elements library with stock starting points, a simple editor and Vera assist. Research (Framer, Webflow, Figma, Canva, Gamma, WordPress, Shopify, SmartArt, Napkin, Datawrapper, Flourish) and a survey of this repo produced the proposal "Theme Element Library" (2026-10-13). Claude Design then wrote the build brief against it and is still drawing the elements; the owner asked to capture the rules now and build when the package lands.

**Decision: the rules.**
1. **One library on the existing block registry.** Tokens feed elements, elements feed presets. No second block system (EDITOR-ARCHITECTURE §1). Five insertable kinds: element, smart (data-bound) element, section preset, theme pack item, saved block.
2. **Roles, never raw values.** Elements read token roles only (`--th-*` for theme roles, `--ig-*` for infographic aliases, the `--design-*` layer). A theme-specific look lives in that theme's manifest `variants` map, never in the element.
3. **Every theme ships a manifest** shaped like the package's `theme-pack.json`: `tokens`, `variants`, `pack[]`, `presets[]`, `fonts`. Default, Bold and Wildheart each get one; Frequency registers as a platform pack. Fonts load per theme, never in `app/layout.tsx` (ADR-1734).
4. **Every pack item names a fallback.** When a site switches theme, pack items swap to their fallbacks and the editor lists what changed.
5. **Truthful by construction.** Every number is `nullable()`. A null value (or `needsValue: true`) renders a dashed "needs a number" pill and blocks publish ("Publish blocked: fill every number"); a missing source renders "needs a source"; starting points ship with empty numbers, never sample figures; every figure shows a source line.
6. **Accessible by construction.** The visual is `aria-hidden`; `describe` is the figure's screen-reader text; a `<details>` "See the data" holds a table generated from the items. Phones: stats grids drop to two columns, timelines run vertical.
7. **Server-rendered, no client JS.** Plain HTML and SVG from the block's props; decorative motion stops under `prefers-reduced-motion`.
8. **The reference output is the spec.** Server output must produce the package's DOM and `.ig-*` class names for the same JSON, so `tokens/infographics.css` ports unchanged. The package's browser scripts are for review only. Check: diff our server output against `guidelines/cards/infographics.html` "Element library" for the same JSON.
9. **Vera drafts the envelope only.** Output is JSON in the shared envelope `{ kind, title, items, source, variant, describe }`, validated against the L0 schema. Every number is checked in code against the owner's text or the Space's data; an unverifiable number becomes null. Totals and percentages are computed in code. Vera never emits styling (ADR-976).
10. **Every new element arrives as a five-part bundle:** token-only CSS (with reduced-motion rules), reference markup rendered from JSON, a schema with example props, a manifest entry (variants, pack entry with fallback, presets), and a preview tile shown on both Stage and Commons.
11. **Icons** come from the design system sprite (`assets/icons/frequency-icons.svg`, 76 symbols including `house-01` to `house-12`).

**The ten v1 kinds** (envelope above; item shape · variants · class): `stats` value, unit, label · grid-2, grid-4, cards · `.ig-k-stats`; `iconList` icon, title, line · rows · `.ig-k-list`; `steps` title, line, icon (+ done) · numbered · `.ig-path`; `timeline` date or time, title, line · vertical · `.ig-k-time`; `comparison` label, values[] (+ columns[], highlight) · columns · `.ig-k-cmp`; `bar` label, value (+ highlight, height) · single · `.ig-k-bar`; `donut` label, value, color? · ring · `.ig-k-donut`; `meter` current, goal, unit, label · tide · `.ig-k-meter`; `pictogram` count, of, icon, label · icons · `.ig-k-pic`; `quote` text, who, role · pull · `.ig-k-quote`. Build order: stats, steps, timeline, comparison, meter; then bar, donut, iconList, pictogram, quote.

**v2 Frequency smart elements** (data · fallback): streak arc (count, best, state[] done/freeze/today/miss · stats); streak thread (state[], days[] · stats); layered bars (sets D/W/M/Y of labels and series · bar); podium (top three as face, name, value · stats); orbit (rings of satellites around a core label · iconList); weave (circles and members on a plane · stats).

**Token roles from the package.** `--th-bg`, `--th-text`, `--th-muted`, `--th-accent`, `--th-r` per theme (Stage: #0A0612, #F6F0FF, #A89BC2, the iridescent sweep, 24px; Commons: #FFFFFF, #34312E, #7C766F, the pastel sweep, 24px). Infographic aliases read the roles: `--ig-fill` accent, `--ig-orb` radial accent, `--ig-track` ink 7%, `--ig-dash` ink 16%, `--ig-ink` text, `--ig-sub` muted, `--ig-hole` background, `--ig-node` node fill. Series palette in order: #C4B8FF, #8FE9FF, #EEC1EC, #A3D4FF, #B3C6FF.

**Build order.** L0 `defineBlock` for new blocks only (Zod schema seeded from the envelope and item shapes, example props, text projection, version) · L1 manifests · L2 the insert panel (tabs Elements, Sections, Live data, Infographics, This theme, Saved; previews from each block's example in the current theme; other themes' pack items hidden) · L3 the Infographic block · L4 Vera compose · L5 saved and synced blocks (not covered by the package) · v2 the Frequency smart elements. Acceptance: every kind renders from valid JSON under Default, Bold and Frequency with no client JS; a null number shows the pill and blocks publish; a theme switch swaps pack items to fallbacks and the editor lists them; every figure has `describe` and a data table.

**Rejected.** A chart library on public renders (none is installed; hand-drawn server SVG already exists in components/admin/spark-charts.tsx and stays the pattern). Required number fields (they push a model to invent figures). Theme forks of elements (variants map instead).

**Consequences.** Nothing is built yet: the owner is still drawing elements, and this record is the contract they land against. ADR-1403 (product first) holds editor work behind launch work; starting L0 is an explicit owner call. docs/EDITOR-ARCHITECTURE.md §11 points here.
