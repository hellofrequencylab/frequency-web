## ADR-1706: The Vercel bill follows the build count, so docs-only pushes do not build, the Sentry upload is quiet and production-only, previews are untraced, and the PWA files skip the proxy (HYG-162)

**Status:** Accepted · 2026-10-05 · backlog `HYG-162` · owner ask 2026-10-05 ("we have GOT to change that observability thing") · re-tested first per [ADR-1082](DECISIONS.md) from the billing export, the runtime logs and one build log · config change in `vercel.json` and `next.config.ts`, code change in `lib/observability/sentry.ts` and `proxy.ts`, no migration

**Context.** The Vercel billing export (FOCUS charges, read 2026-10-05 for 28 of September's 30 days) totals $702: Build CPU Minutes $265, Observability Events $234, CDN Requests $59, Fast Origin Transfer $53, the rest under $35 each. The two large lines move with the number of builds, not with members. 2026-09-19 billed $33.57 of build and $18.11 of observability on a day of many merges; 2026-09-12, 2026-09-26, 2026-10-02 and 2026-10-03, days with no build, billed under ten cents of each. The prefetch loop of [ADR-1617](DECISIONS.md) (550,000 runtime lines a day on 2026-09-27 to 29) did not lift the observability line above the build-heavy days, so it was not the main driver.

Three readings explain the shape:

- **A build writes about 10,000 log lines**, and nearly all of them are the Sentry webpack plugin listing every `.js.map` it uploads. `silent: !process.env.CI` was meant to keep local builds quiet; Vercel sets `CI`, so the loud path was the only one that ever ran. Vercel bills build log lines as observability events.
- **Preview deployments carry the runtime volume.** In the 24 hours to 17:00 UTC on 2026-10-05, production wrote about 3,500 runtime lines (3,400 of them crons) and the previews about 52,000: the e2e, visual and Lighthouse runs. The DSN is set for preview as well as production, so every one of those runs was also a traced Sentry session at the production sample rate. `/sw.js` and `/offline.html`, fetched by the service worker on every page it controls, were about 2,800 proxy invocations a day on their own, each a Supabase session read for a file no one is signed in to.
- **Many builds buy nothing.** Six threads merge in parallel ([ADR-1635](DECISIONS.md) fragments, ADRs, docs), and 57 deployments ran on 2026-10-05 before 17:00 UTC. A push that touches only documentation produces a byte-identical artifact; no gate can fire on it and the e2e workflow's path filters already ignore it.

**Decision.**

1. **`vercel.json` gets an `ignoreCommand`: `node scripts/vercel-ignore-build.mjs`.** The script skips a build only when every file changed since the branch's last successful deployment (`VERCEL_GIT_PREVIOUS_SHA`) is documentation: `docs/**`, any `*.md`, `.claude/**`, `scripts/planning-docs.txt`, `LICENSE`. Everything else builds, `.github/**`, `test/**` and `public/**` included, because workflows and tests decide what runs against the preview. No previous SHA, a shallow clone that cannot diff, or any error means build. It applies to production too: a docs-only merge to `main` leaves the current production deployment in place, which is the same artifact. `--probe` runs the classifier against fixtures and reads `vercel.json`, so the wiring is a `pnpm check:backlog` probe, per the fail-safe rule in AGENTS.md.
2. **The Sentry upload is `silent: true`, `telemetry: false`, and uploads source maps only when `VERCEL_ENV === 'production'`.** Upload failures still warn and continue, which is the plugin's default and the behaviour before. A preview's stack traces are read by nobody, and the upload was the slowest step of the build.
3. **`tracesSampleRate` is 0 on a preview deployment** (`lib/observability/sentry.ts`), 0.1 in production as before, 1.0 in development as before, `SENTRY_TRACES_SAMPLE_RATE` still overrides. Errors on previews still report.
4. **The proxy matcher excludes `sw.js`, `offline.html` and `manifest.json`** on the same test as the HYG-048 crawler files: never a human's landing page, never tenanted, never behind auth.

**Not done here, and why.** Observability Plus itself, the OTLP trace drain's sampling, the build machine size, on-demand concurrent builds and Skew Protection are project settings in the Vercel dashboard, which no file in this repository controls; they go to the owner as steps, with the thread reply as the record. The cron schedules (`process-queue` every two minutes, four jobs every five) are 3,400 invocations a day and billed in cents; they stay. The e2e, visual and Lighthouse suites stay as they are: they are the one check that reads a preview, and their cost is per PR, not per push, once docs-only pushes stop building.

**Consequences.** The build line falls with the share of pushes that are docs-only and with the shorter upload; the observability line falls by the build-log share and the preview trace and proxy share. The row's expected lift is $150 to $250 a month at September's pace, before the dashboard steps. The real number is the owner's billing read 24 hours after this deploys, and that read, not this ADR, closes the row. A code change inside a path the classifier calls documentation would skip a build that mattered; the list contains no such path, and the test and probe pin it.

**Rows.** HYG-162.
