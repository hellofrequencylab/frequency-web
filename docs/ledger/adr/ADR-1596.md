## ADR-1596: Every Loom download goes through one server door that applies the asset's policy to the caller, writes an append-only record first, and hands a protected original out only as a one-minute signed attachment (LIVE-578)

**Status:** Accepted · 2026-09-29 · backlog `LIVE-578` (closed here) · child 3 of `PROG-D6` under [ADR-1562](DECISIONS.md) (§1 item 3, §5) · builds on [ADR-1595](DECISIONS.md) (the private bucket and `signedLibraryAssetUrl`) · re-tested first per [ADR-1082](DECISIONS.md) · numbered 1596 by the orchestrator's assignment for this wave

**Context.** Re-tested on the LIVE-577 tree (`claude/live-577-loom-private-originals` at `8df84fe36`) on 2026-09-29, from the repo only. The drawer's Download (`app/(main)/admin/library/loom-grid.tsx` `downloadFile`) called `downloadImageUrl(asset.url)` in `lib/library/export-svg.ts`: a browser `fetch` of the url with a `window.open` fallback. There was no server door under `app/api/library/`, `download_policy` was read by the store and the drawer's select and compared to no caller anywhere, and no table recorded a download. With LIVE-577 a protected row's url in the Studio is a one-hour signed original, so the same button handed that hour-long link to the browser. The premise held.

**Decision.**

1. **One door, `GET /api/library/download/[id]`.** The route establishes the caller first (`getCallerProfile`, null when signed out) and hands off to `openLibraryDownload` in `lib/library/download-door.ts`, which: reads the row by id (a malformed id, a missing row, or a row with no file is 404); refuses an expired license for everyone, staff included (410); applies `download_policy` (`open`: anyone who reached the link; `members`: a signed-in profile, else 401; `staff`: the Loom Studio gate, `authorizeAction(caller, 'janitor', 'marketing')`, the answered twin of the page's `requireAdmin('janitor', { staff: 'marketing' })`, else 403); mints where the file is; writes the record; then answers `302` with `cache-control: no-store` and `referrer-policy: no-referrer`. A refusal answers the sentence that says why, in plain text, and no file. An unknown stored policy reads as `staff` at the door (the strictest misreading; the CHECK constraint makes it unreachable).
2. **A protected original leaves only as a one-minute signed attachment.** `signedLibraryAssetUrl` stays the one signing function and gains an optional `{ download }` that storage turns into `Content-Disposition: attachment`; the door always passes `LIBRARY_DOWNLOAD_TTL_SECONDS = 60`. An unprotected file redirects to its public url with storage's `download` query flag; a url that is not a storage url is passed through unchanged.
3. **The record is append-only and comes first.** `20270345009560` creates `public.library_downloads` (`id`, `asset_id` on delete cascade, `profile_id` on delete set null, `policy` as text as it stood, `created_at`), RLS on, one policy (staff read through `private.get_my_web_role()`), no insert, update or delete policy, `revoke all` from anon and `revoke insert, update, delete, truncate` from authenticated, so the service role the door runs as is the only writer. The mint happens before the insert and the redirect after it: a failed insert answers 503 and the minted URL, never sent, dies inside its minute. A failed mint answers 503 and writes nothing.
4. **The drawer goes through the door.** Download is a plain link to the route, shown for any row with a file (a protected row whose one-hour mint failed still has its storage path). The drawer reads the record back through a Studio-gated action (`libraryDownloadRecord`) and shows the count and last date under `[data-loom-downloads]`. `downloadImageUrl` is deleted: it was the browser path that asked nothing, and a code-drawn element never used it (its SVG and PNG exports render from the DOM).

**Rejected.** A browser `fetch` of the route to keep the old blob download (it follows the redirect, loads the whole file into memory, and the fallback `window.open` would record a second download). Recording after the redirect (a download that cannot be recorded is the one the policy exists for, ADR-1562 §5). A table grant verdict of `internal` (the row asks for a staff read, which is a policy). Adding the table to `scripts/rls-deny-surface.txt` now (it does not match the census heuristic; `supabase/tests/library_downloads.test.sql` proves the deny matrix directly). A Space-member reading of `members` (the row and ADR-1562 say a signed-in profile; a per-Space download policy is its own ruling).

**Consequences.** ✅ Who took a Loom original, when, and under which policy is written down before the file leaves, and nobody but the service role can write or rewrite it. ✅ `members` and `staff` mean something: a signed-out visitor and a non-staff member are refused with a sentence. ⚠️ An `open` protected asset is served to anyone holding its door link, which is what `open` says; the id is a UUID and the Studio is the only surface that prints it today. ⚠️ The drawer's Open link still shows the Studio's one-hour signed original for a protected row until LIVE-580 renders proofs. ⚠️ The migration must be applied before the route can record anything; until then every download answers 503 (fail closed).

**Rows.** `LIVE-578` (closed here). `PROG-D6` (open, proven by its children; LIVE-580 remains).
