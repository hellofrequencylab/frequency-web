## ADR-1637: safeImageSrc returns only a value that has just passed an anchored, wildcard-free regexp, so a crafted blob: or data: string cannot reach an img src (HYG-142)

**Status:** Accepted · 2026-09-29 · backlog `HYG-142` (closed here, filed by `HYG-138`) · the CodeQL follow-up the HYG-137 work named · numbered 1637 because 1619 and 1636 are claimed on open PRs

**Context.** Re-tested first (ADR-1082). `safeImageSrc` parsed the string, checked the scheme, and handed back `URL#toString()` or the data: input. A blob: path and a data: body are opaque to the URL parser, so `safeImageSrc('blob:https://app.local/"><img src=x onerror=alert(1)>')` and a data:image value carrying a quote came back verbatim. The HYG-142 probe failed on this tree on that first hostile value. CodeQL js/xss-through-dom does not model a scheme check as a sanitizer, and it kept flagging the image picker (`components/ui/image-focal-picker.tsx` via the paste field in `components/ui/image-upload.tsx`). An `<img src>` still cannot execute script; the defect is the class, not an active exploit.

**Decision.**

1. **Every non-null return is `if (RE.test(s)) return s`.** Four fully anchored, wildcard-free literals: a same-origin path (leading slash, first character not another slash, so `//host` is out), `data:image/(png|jpeg|jpg|gif|webp|avif);base64,` plus a base64 body, `http(s)://host` with an explicit path/query character class (no credentials, quotes, angle brackets, backticks, spaces or backslashes), and `blob:http(s)://host/<uuid>`. Everything else is null.
2. **The value returned is the string that passed, not a re-serialisation.** CodeQL's sanitizer shape is a regexp test on the value that reaches the sink. Re-parsing and handing back `toString()` is how the quote in a blob path used to survive.
3. **Inline SVG data: URLs are refused.** They were allowed under a prefix test; they are not a raster preview and they are the vector CodeQL names. QR and Loom icon data URLs do not go through this helper.
4. **Fix, never dismiss.** No `codeql[...]` comment, no workflow exclusion. The allowlist is the sanitizer.

**Rejected.** Keeping the parser and adding an extra character blocklist (the parser still would not see inside a blob path). Dismissing the image-picker alert. Splitting node_modules and compiler-cache ratios (that is HYG-136, already in flight elsewhere).

**Consequences.** A pasted URL that is not one of the four shapes renders no image. A `createObjectURL` preview still works: those strings are `blob:<origin>/<uuid>`. `safeUploadPreviewSrc` stays stricter (blob or http(s) only) and now shares the same two literals. Other CodeQL alerts stay HYG-143.

**Rows.** `HYG-142` (closed). `HYG-143` stays open.
