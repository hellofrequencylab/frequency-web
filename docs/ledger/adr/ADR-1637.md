## ADR-1637: safeImageSrc returns only a value that an anchored, wildcard-free regexp just accepted, so a blob or data: string cannot carry quotes into an img src (HYG-142)

**Status:** Accepted · 2026-09-29 · backlog `HYG-142` (closed here) · applies the anchored-allowlist sanitizer shape to `safeImageSrc` · extends [ADR-1082](DECISIONS.md) (re-test the premise) · no migration

**Context.** HYG-142's probe failed on this tree for the reason the row named: `safeImageSrc('blob:https://app.local/"\><img src=x onerror=alert(1)>')` came back verbatim. The helper parsed with `new URL` and checked the scheme. A blob path and a data: body are opaque to the URL parser, so quotes and angle brackets survived, and CodeQL `js/xss-through-dom` does not model a scheme check as a sanitizer. The path it draws is `components/ui/image-upload.tsx` (a pasted URL) → `components/ui/image-focal-picker.tsx:225` (`<img src={safeImageSrc(imageUrl)}>`). As with the upload-preview helper, no script runs in an `<img>`; the fix is the class.

A parse-and-re-serialise also rewrote same-origin paths (`/loom/../loom/a.jpg` became `/loom/a.jpg`). That was a different answer than "only these characters", and it is not the shape CodeQL models.

**Decision.**

1. **`safeImageSrc` returns only from `if (RE.test(safe)) return safe`.** `safe` is the trimmed input. Every other return is `null`. Each `RE` is a fully anchored literal with no bare dot, negated class, or `\S`/`\W`/`\D`.
2. **Four product shapes, plus the site-icon exception.** A same-origin path (`/images/hero.png`, `/api/og?title=x`). A raster `data:image/{png|jpeg|gif|webp|avif};base64` body. An `http(s)` URL with a host, an explicit path, and a query of explicit characters (no credentials, quotes, angle brackets, backticks, spaces or backslashes). A `blob:http(s)://host[:port]/<uuid>`, which is what `URL.createObjectURL` mints, including `localhost:3000`. A fifth pattern allows `data:image/svg+xml,` with a percent-encoded body so a Loom site icon still previews; `data:image/svg+xml,<svg onload=alert(1)>` stays out because `<` is not in the class.
3. **Fix, never dismiss.** Inline `// codeql[js/xss-through-dom]` comments do not move GitHub code scanning. The helper itself is the sanitizer. `safeUploadPreviewSrc` stays a filter on top of this helper; rewriting that sibling into the same shape is a later row, not this one.

**Rejected.** Keeping the URL parser and adding an extra character denylist (CodeQL still would not model it, and a blob path would still be opaque). Dismissing the focal-picker alert. Passing the caller's string through on a leading slash (the 2026-08 pass-through this file already retired once).

**Consequences.** A crafted blob id or a data: body with a quote reaches no `<img src>`. A stored site icon still paints. A same-origin string with `..` or a space is now refused rather than rewritten, and the Loom image field shows "Choose a photo" for it. The probe imports the helper under type stripping: five real sources pass unchanged, eight hostile values return null, and the body has no non-null return past the regexp tests. HYG-143 still owns the remaining CodeQL set.

**Rows.** `HYG-142` (closed here). Untouched: `HYG-143` (the open-alert set). `safeUploadPreviewSrc` is still a prefix filter on this helper.
