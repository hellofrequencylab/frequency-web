## ADR-1976: A run in flight at a release gets 7 days to finish on its own edition (2026-11-16)

**Date:** 2026-11-16 · **Status:** accepted (owner decision, Daniel, 2026-11-16, decision card "7-day grace to finish"); dark until HUNTS_CLAIMS_ENABLED is on and the migration is applied · **Rows:** FH-044S, FH-044T · **Builds on:** [ADR-1972](DECISIONS.md), answering its open question (a) and replacing its point 6

**Context.** ADR-1972 pinned every run to the edition it started on and left one question for the owner: when a new edition is released, may a run already in progress finish on the old one, or does a new season start everyone fresh. Until now the claim command answered `version_superseded` to any run whose edition was no longer the Hunt's current one, so a player half way through lost the rest of it at the moment of release.

**Decision.**
1. **Seven days, then a record.** An active run on a replaced edition keeps checking in on that edition, by that edition's rules, missions and printed-code bindings, for 7 days after the release that replaced it. After that it is a frozen record and `hunt_claim_apply` answers `version_superseded`, exactly as before.
2. **The release time is the next edition's `published_at`.** The window starts at the `published_at` of the first later edition that went out (published, or since superseded). The column exists since the schema migration and the FH-044 freeze trigger makes it immutable once published, so no column is added and the window cannot be moved after the fact.
3. **The database is the authority.** `hunt_claim_apply` (migration 20270346085000_hunt_edition_grace.sql) checks the window under the run lock and otherwise behaves exactly as its 20270346081000 definition. `EDITION_GRACE_DAYS` in lib/hunts/editions.ts states the same number for the screens, and a test holds the two together.
4. **A scan finishes the old run first.** lib/hunts/claim-store.ts credits the member's own active run on a replaced edition while its window is open, the code is bound to a stop on that edition, and that stop is still owed. Otherwise the scan goes to the run on the current edition, as before. The player page shows the old run, the day its window closes, and older rewards.
5. **The author sees the cost before the tap.** The editor's release step shows where each printed code goes, how many codes retire, and how many people are part way through the outgoing edition with their 7 days.

**Consequences.** For a week after a release one printed code can count for two editions; the run it credits is decided by point 4, and the new edition's run keeps its own progress. Applying the migration and walking one pilot Trail through a release with real printed codes are FH-044T.
