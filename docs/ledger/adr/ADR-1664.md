## ADR-1664: An App an operator turns off at global scope is off on every page, because the one override map every App surface reads carries the global disables (LIVE-686)

**Status:** Accepted · 2026-09-29 · backlog `LIVE-686` (closed here, filed by the DEF-DOMAIN split, ADR-1624) · numbered 1664 by the orchestrator's assignment · re-tested first per [ADR-1082](DECISIONS.md) · no migration

**Context.** App overrides (`app_overrides`, [docs/ADMIN-RAIL.md](ADMIN-RAIL.md) Phase 6) are stored per scope KIND. The (main) layout loaded only the page scope's rows (`loadCachedAppOverrides(scopeKeyFor(pageScope))`) and threaded them into `PageAdminProvider`, which the settings panel hook (`useSettingsPanel`: the desktop drawer, the phone sheet and the rail search) reads. So a disable saved at `global` stopped at global pages. The panel's own comment named "threading the global overrides onto entity-scope pages" as a follow-up.

Re-tested on main at `7a051af6e` before the change. The row's wording does not hold as written: on circle, event and Space pages the panel resolves NO personal App at all (the personal set mounts only on the global and profile scopes, "fix E"), and no catalog App declares both `global` and an entity scope. The consequence it names is real on the one non-global scope that does carry the personal set: `/people/<handle>` resolves to the `profile` scope, so it read the profile rows and applied no override to the personal set. The Profile, Spotlight, Layout and Spotlight appearance editors mount only there (their surface predicate is `/people/*` plus `/settings/profile`, where the hub drops them), so an operator's global disable of any of them changed nothing on any page. And because `setAppOverride` accepts any known App id at `global`, a stored global disable of a circle, event or Space App was ignored on its own page.

**Decision.**

1. **One resolver.** `resolveScopeAppOverrides(scopeKey, read)` in `lib/apps/overrides.ts` is the override map for a scope: that scope's own rows plus every App disabled at `global` (`withGlobalDisables`). The global scope reads once and is its rows as stored. Both server readers go through it: the shell's cross-request cached `loadCachedAppOverrides` (`lib/layout/chrome-sources.ts`) and `resolveAppsForScope`. The editor's `loadAppOverrides` stays the raw per-scope read, so the manager shows what was saved at each scope.
2. **The global disable wins.** A global disable beats an explicit enable saved at the page scope. The scope's own position and role floor for that App are kept.
3. **Only the disable travels.** A global `position` or `min_role` is about the global rail and does not reach another scope, as the row asked.
4. **The panel applies the disable to the personal set off the global scope** (`dropDisabledApps`: presence only, no reorder, no floor). At global scope it keeps the whole overlay, as before.
5. **Fail-safe per key.** Each key's read degrades to `{}` on error, so a failed global read leaves the page's own rows and a failed page read leaves the global disables.

**Rejected.** Filtering at each surface (drawer, sheet, search, bank): four places to drift, and the row is about one rule. Folding the global position and role floor too: the row scoped it to the disable, and a global floor would hide a member's own Profile editor on their own page. A migration or a new scope key: the rows are already there.

**Consequences.** One more cached read (`global`, the same entry every global page already fills) on non-global pages; no query on a cache hit. Operators get what the switch says: off for everyone means off on every page kind. No member-facing copy changes, so no help page.

**Rows.** `LIVE-686` closed here. Tests: `components/layout/settings-panel.global-disable.test.tsx` (the real panel hook on a global, profile, circle, event and Space page: the App shows with no override and is gone once disabled at global only; a global disable beats a scope enable; a global floor does not travel), `lib/layout/chrome-sources.app-overrides.test.ts` (the shell loader over a fake table, per kind, fail-safe per key), `lib/apps/overrides.test.ts` (the pure fold). Each page-kind case fails on the pre-change code.
