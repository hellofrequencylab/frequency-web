## ADR-1661: Clicking into a field never glows the brand orange, anywhere (LIVE-657)

**Status:** Accepted · 2026-09-29 · backlog `LIVE-657` (closed here) · owner ruling S8 (2026-06-05 screenshot review, "No orange highlight on input focus, site-wide") · no migration

**Context.** The kit already obeyed the ruling. `fieldClasses` in `components/ui/field.tsx` focuses a field with a calm neutral halo (`focus:border-border-strong focus:ring-2 focus:ring-border-strong/30`), and `components/ui/field.test.tsx` pins it. Hand-rolled controls did not. Re-tested on main at 60567b67e: 14 files still spelled out `focus:border-primary` or `focus:ring-primary`, as the row said. Three more bordered wrappers around a seamless `Input` lit `focus-within:border-primary`: the pay-what-you-want amount, the shop item tag row and the listing offer field. They glow orange the same way when a member clicks in. No check counted any of them.

**Decision.**

1. **Every site takes the primitive's halo, token for token.** `focus:border-primary` becomes `focus:border-border-strong`, `focus:ring-primary` (any alpha) becomes `focus:ring-border-strong/30`, and `focus-within:border-primary` becomes `focus-within:border-border-strong`. A site that drew only a border still draws only a border, so no layout moves. The admin settings search used `ring-1` in primary and now wears the primitive's `ring-2` halo.
2. **The two Airwaves checkboxes drop the class.** `focus:ring-primary` with no ring width and no forms plugin painted nothing. The `Checkbox` primitive deliberately carries no focus class and leaves focus to the global rule, so these two now match it.
3. **Keyboard focus is untouched.** The unlayered `:focus-visible` rule in `app/globals.css` still paints `--color-focus-ring` on every button, link and field (WCAG 2.4.7, guarded by `scripts/check-focus-visible.test.ts`). The ruling is about the glow you get from clicking into a field. `focus-visible:ring-primary` on actionable chrome is out of scope.
4. **A guard stops it coming back.** `scripts/check-field-focus.test.ts` walks `app/`, `components/` and `lib/` with tests excluded and comments blanked. It fails on any `focus:` or `focus-within:` border or ring in the primary colour, including `primary-hover`. Mutation-checked by restoring one site. Since no check counted these before, there was no baseline to lower.

**Consequences.** One focus look for every field, and a single rule makes it permanent. `node scripts/check-adoption.mjs` does not move, because only colour tokens changed. The backlog probe fails on main with 16 files and passes here, and its second arm fails if the field primitive loses the neutral halo.
