## ADR-1737: One setting picks the platform's design system, DAWN or Frequency, and Frequency overrides every older theme layer

**Status:** Accepted · 2026-10-13 · backlog `LIVE-908` · owner-ruled · sits above [ADR-249](DECISIONS.md) (skins) and the four-axis model in docs/THEME.md · beside [ADR-1736](DECISIONS.md) (the name Frequency)

**Context.** The owner is replacing DAWN with a new design system, Frequency, and asked for a one-button change-over: "The only two themes for the main site should be DAWN and Frequency", "The new Frequency theme will override everything. Midnight will become a theme for users." The survey of 2026-10-13 found colour about 99% on tokens but four things a token swap could not reach: `@theme inline` held the shadows, the radius steps (`rounded-sm` to `rounded-2xl`, about 2,200 call sites) and the body font as literals, which Tailwind compiles into each utility; the browser chrome colour and the MapLibre maps carried their own DAWN hex; five older theme layers (skins, generations, occasions, Space font sets and accents, Theme Studio `<style>`) re-point tokens below the shell root, where a site-level value cannot win; and the root layout must stay static, so a per-request switch was ruled out.

**Decision.** (1) **The switch.** `lib/theme/design.ts`: `DesignId = 'dawn' | 'frequency'`, `SITE_DESIGN` read once from `NEXT_PUBLIC_SITE_DESIGN` (unset or unknown reads as DAWN). `app/layout.tsx` stamps `data-design` on `<html>` statically, so prerendering holds and the first paint is already the right system. (2) **One sheet per design.** DAWN stays the unscoped `:root` / `.dark` blocks. Every other design is `app/themes/<id>.css`, scoped to `:root[data-design="<id>"]` and `.dark[data-design="<id>"]`, redefining DAWN's own token names only; `lib/theme/design.test.ts` fails on a name DAWN does not define and on a rule outside the scope. (3) **The design layer.** The literals `@theme inline` held now read `--design-*` variables at DAWN's exact values (radius steps, the nine shadows, body, display and mono fonts, the map paint), so a design redefines `rounded-lg` or `shadow-md` and every call site follows without a codemod. Tailwind can no longer recolour a variable shadow, so the four tinted CTAs use `shadow-glow-primary-sm|lg`. (4) **Frequency overrides everything.** `LEGACY_THEME_AXES` is false for Frequency: the resolver returns the default skin, `balanced` and no occasion; the member layout drops the Theme Studio `<style>`; `AccentScope` drops the Space accent and font set; Settings hides Feel and Seasonal accent; Theme Studio says it is paused. (5) **Midnight is a member theme.** `selectable: true`, and `SkinDef.designs` scopes it to DAWN until a Frequency Midnight is authored; `resolveSkin` returns `default` for a skin outside the active design. (6) **Browser chrome and maps follow the design.** `THEME_COLOR_LIGHT/DARK` come from the design registry; the Circle, Discover and scan maps read `--design-map-*` at mount (`lib/maps/css-color.ts`). (7) **Local preview.** `?design=<id>` stores a token-only preview that the pre-paint script stamps; `?design=off` clears it. A true check of a design is a build with the env var set.

**Rejected.** A runtime cookie switch (it makes the root layout dynamic and costs prerendering on marketing and /discover). Moving DAWN's tokens into their own scoped sheet (five guard tests parse the first `:root`, and DAWN as the unscoped base means an unknown design falls back to a complete system). A codemod of the 2,234 literal `rounded-*` steps (the steps themselves now belong to the design). Making Frequency a skin (skins retune colour and corner roles only and are resolved per request inside the member shell).

**Consequences.** Switching design is one environment variable and a redeploy. The Frequency sheet is a scaffold until the design system export lands; until then Frequency renders as DAWN with the older layers off. OG images, transactional email and the Wallet pass read `lib/theme/palette.ts` (design-keyed, DAWN byte-identical, held against `:root` by its test). Still DAWN-only: the PWA manifest colours (a Frequency deploy must write them from the design), `app/dev/og-root-card` (its authz-ledger fingerprint needs a human re-review before it can change), the pre-DAWN indigo in event reminders and outbound batches, and neutral greys in older email builders. `scripts/probes/design-switch.mjs` holds the switch, the design layer, the legacy gates and Midnight for LIVE-908.
