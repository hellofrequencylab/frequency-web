## ADR-1642: The privacy policy says what the code does: export and deletion are linked as self-serve, every processor the code calls is named, and docs/APP-STORE-PRIVACY.md maps the data to the App Store label and the age rating (LIVE-724)

**Status:** Accepted · 2026-09-29 · backlog `LIVE-724` (closed here) · filed by HYG-146 under [ADR-1650](DECISIONS.md) (the iOS readiness ruling) · no migration

**Context.** Re-tested on `main` at `bc1913405` on 2026-09-29 (ADR-1082). `app/privacy/page.tsx`, last updated June 23, 2026, told members "To request a full data export or account deletion, contact us at hello@frequencylocal.com", though both have been self-serve in Settings since H2-5 (`lib/privacy/export.ts`) and LIVE-549 (`lib/account.ts`, `lib/account-erasure.ts`), in the Account and privacy section at `/settings#account` (`/settings/account` redirects there in `next.config.ts`). Its processor list named Supabase, Vercel, Google, Stripe and Resend. The code also calls Anthropic (`@anthropic-ai/sdk`, every AI path through `lib/ai/client.ts`), Sentry (`@sentry/nextjs`), Twilio (`lib/comms/sms-send.ts`, fail-closed), Upstash (`lib/rate-limit.ts`), OpenFreeMap (`lib/maps/provider.ts`), Photon (`lib/geocode.ts`), Nominatim (`lib/events/nominatim.ts`), ipapi.co (`lib/geolocation.ts`), Recraft (`lib/loom/recraft.ts`, offered to members through `lib/loom/cover.ts`) and the browsers' push services (`web-push`, `lib/push.ts`). It said nothing about push subscriptions, live or claim-time location, the camera, SMS consent evidence, Vera's memory, or the 90-day purge of raw interaction events (`lib/consent/retention.ts`). Nothing recorded what the App Store privacy label and age rating questionnaire will ask.

**Decision.**

1. **Only the factual sections change.** Section 2 (what we collect) gains location, camera and photos, push, phone number, payments, Vera's memory, and a corrected usage-data paragraph. Section 3 gains three uses. Section 4 names every processor that receives member data and what each receives. Section 7 links `/settings#account` for Download my data and Delete account, says what deletion removes and keeps as the code does it, and says how to turn push, texts and analytics off. The structure, numbering, legal voice, Google Limited Use section and contact stay; Last updated moves to September 29, 2026. A CHANGELOG line says so.
2. **A processor is named when the code calls it and member data reaches it.** Healthchecks (cron names only) and Brave Search (operator imports of business names) are in the inventory, not the policy.
3. **`docs/APP-STORE-PRIVACY.md` is the reference for the App Store label.** Every Apple data type, collected or not, linked or not, tracking (none), purpose, and the table, bucket or processor that proves it; the processors with what each receives; and the age rating inputs (18+ per the terms, user-generated content with report and block, chat, in-person meeting and an opt-in romance lane, unrestricted web links, wellness topics, no gambling or ads). It points at the backlog for status. A change that adds a processor or a data type updates the policy and the inventory in the same PR.
4. **Nothing a lawyer should decide is written as a commitment.** No legal bases, no retention period the code does not enforce, no vendor promise (such as model training) the code cannot show. Those are listed for counsel in the PR.

**Rejected.** Rewriting the policy into a new structure (the row asks for facts, and a restructure is a legal review of its own). Listing every host the code touches (demo image hosts and link previews carry no member data). A separate help page for export and deletion (the policy links the real section; `content/help` can follow).

**Consequences.** The live policy stops sending members to email for rights they already have, and names the vendors that actually see their data. The row's probe derives the processor list from the code (seven dependencies in `package.json`, seven hosts in `lib`, `app`, `components`), so a new vendor that the policy does not name fails `check:backlog`; it also proves the link lands on a section that renders the download and the delete, and that the inventory maps every data type with age rating inputs. Mutation-fired: 28 of 28 arm mutations fail it. Fails on `bc1913405` at the first arm.

**Rows.** `LIVE-724` (closed here). Related, untouched: `LIVE-723` (the member-content rules, report and block in the app), `LIVE-726` (Apple in-app purchase), `DEF-MOBILE` (the native app, parked).
