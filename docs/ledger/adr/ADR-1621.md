## ADR-1621: The load and soak harness ships before its number: scripts/load-soak.mjs drives the five hot paths against a preview, judges them against slos.ts, refuses production twice, and never runs against a deployment from CI (LIVE-551)

**Status:** Accepted · 2026-09-29 · backlog `LIVE-551` (unparked and closed here) · child 7 of `DEF-HARDEN` under [ADR-1561](DECISIONS.md), which stays open on `OWN-082` · answers the owner ruling of 2026-09-29 ~18:00Z ("pull it into this cycle now"), which supersedes for this row the 03:45Z "keep gated on the number" ruling and the [ADR-1573](DECISIONS.md) park to 2027-01-05 · re-tested first per [ADR-1082](DECISIONS.md)

**Context.** Every H3 scale claim in the hardening plan ("beats its SLO at 10x current load") was unprovable, because nothing in the repo could put load on a hot path and read the answer back against the SLO table. Re-tested on `main` at `d332f1335`: no k6, artillery or autocannon in `package.json`; nothing under `scripts/` or `test/` loads anything; `scripts/perf-baseline.mjs` times one request at a time (a floor, not load) and, for People directory, times `/people`, which is a redirect into `/network` (ADR-172). LIVE-551 filed the harness gated on a number (1,000 profiles or a hot-path p95 over its SLO) on the argument that a harness built early measures only itself. The owner ruled to build it now. What the ruling does not change is §2b's own gate: a reading taken against today's dataset is still not a baseline. And one fact shapes everything below: local, preview and production share one Supabase project (`docs/WORKFLOW.md`), so load on a preview is load on the production database.

**Decision.**

1. **One plain-node script, no new dependency.** `scripts/load-soak.mjs` uses `fetch`, `node:http` and the `scripts/probe-ts.mjs` resolver the repo already has. k6 would add a binary CI does not carry and a second language for five paths; autocannon and artillery would add a dev dependency for what a few hundred lines of node do in the same process as the test.
2. **It judges against the shipped SLO table, never a copy.** The table is read from `lib/observability/slos.ts` in a child node (the `cron-freshness.mjs` pattern), and a table missing `latency.read-hot-paths`, `latency.practice-log-write` or `error-rate.requests` exits 3 rather than printing a report with a blank target column.
3. **The five §2 hot paths as HTTP, the load as an open model.** Feed, Circle detail, People directory (`/network`), Events catalog, and the practice-log write as a Server Action POST carrying the build's `Next-Action` id. Request *i* is due at *i / rps*; a slot that finds the concurrency cap full is dropped and counted as a breach, so a saturated target cannot hide behind a slower clock. Latency runs to the last byte of the body. Profiles: steady, spike (base, 10x, base, the plan's done-when) and soak.
4. **Four verdicts, never a silent pass.** `pass`, `breach`, `unmeasured` (most answers were redirects or 401/403: a login bounce is not the page) and `skipped` (a named missing input). A run with any path not measured is `incomplete`, not `pass`.
5. **Production is refused twice, and a preview is treated as what it is.** By host before any request (`frequencylocal.com` and subdomains, plus `LOAD_SOAK_PRODUCTION_HOSTS`), and by `build.env` at `/api/status` (production, or a remote target that cannot answer). Only `--allow-production` lifts either. No flag lifts the 100 rps ceiling. There is no default target, the write path is off unless `--writes` with a session and the action id, and the two secrets come from env and are never printed or reported.
6. **CI tests the harness, never a deployment.** `--smoke` runs every path, the write included, against an in-process mock on 127.0.0.1 with the real SLO table, and `scripts/load-soak.test.ts` covers the locks, profiles, verdicts and the mock end to end. No workflow invokes it against a URL.

**Rejected.** Waiting for the number (overruled by the owner; and a harness that exists is what lets the number be read under load once it arrives). A CI or scheduled job loading each PR's preview (every preview reads production's database, so that is a production load test on every push). Re-typing the SLO targets into the script (the drift `slos.ts` exists to prevent). Fixing `perf-baseline.mjs`'s `/people` route in this change (the harness uses `/network`; the floor script is a separate row's file).

**Consequences.** An H3 change can now be checked under load: `node scripts/load-soak.mjs --target <preview> --profile spike` gives a per-path p95 and error rate against §4, in a report that states build, commit, data volume and region. OBSERVABILITY-BASELINES §2d is the how-to, §5 lists the commands and env, and RUNBOOKS section 4 says to run it after an incident on the fix's preview, never during one. §2b stays empty under its own gate; no run against any deployment was made in this change. `pnpm packets` no longer lists the load harness among parked work.

**Rows.** `LIVE-551` (unparked: `ownerAction` and `parkedUntil` removed; closed with a cmd probe that runs the smoke, reads `slos.ts` and fails on `main`). `DEF-HARDEN` unchanged and open (`OWN-082`).
