## ADR-1674: The Loom picker stops promising "generate new Elements (coming soon)", and the aiCreate toggle nothing read comes out with it (LIVE-656)

**Status:** Accepted · 2026-09-30 · backlog `LIVE-656` · re-tested first per [ADR-1082](DECISIONS.md) · owner approved building it 2026-09-30 · follows PROG-D7's close · amends docs/EMBEDDABLE-ELEMENTS.md "First citizen" · no migration

**Context.** Re-tested on `main` at `f7f7d3075`. The Elements view of `components/loom/loom-picker.tsx`, the one image picker every upload opens, still read "Upload generated art here, or generate new Elements (coming soon)." PROG-D7 (Loom D7: semantic + AI) closed on 2026-09-29 through LIVE-586 to LIVE-589 (the hybrid ranking, auto-tag, describe on view, upscale) and kept the Weave generative composer a non-goal, so nothing was built for that line to open. Generation does exist, in the Loom Studio at `/admin/library` (the Recraft and create studios), which most picker users cannot reach. The promise had a flag behind it: the `loom-picker` registry entry carried an `aiCreate` toggle ("AI Create", editor role, off by default) that `lib/loom/picker-actions.ts` resolved into `LoomPickerConfig.aiCreate`, and no code read. An operator could switch it on in `/admin/elements` and nothing would change.

**Decision.**

1. **The line says what the view is.** "Elements are the images in this library that were made with AI." No offer of a control that does not exist.
2. **The dead flag comes out everywhere it lived.** The registry feature, the `LoomPickerConfig` field, both default configs (the server's and the picker's fallback) and the resolver line. `/admin/elements` stops offering the toggle. A stored `aiCreate` value in `element_settings` is dropped by `normalizeElementConfig` like any unknown key, so no migration and no data change.
3. **Every working option stays as it was.** The Images, Icons, Elements and Tags views, the scope rail, the Elements grid's AI-made-only filter, upload, search and pick are untouched. `components/loom/loom-picker.test.tsx` (new) renders the picker with the actions mocked and asserts all of that, plus the absence of the promise and of any generate button.

**Rejected.** Linking the line to `/admin/library` (a staff route, so the link would dead-end for a member or a Space host, which is the failure the row names). Wiring `aiCreate` to a real in-picker generator (that is the Weave composer PROG-D7 ruled a non-goal, and it would be a new spend path, not a cleanup). Leaving the toggle registered for later (a switch that does nothing is the same dead promise, one screen over).

**Consequences.** The picker makes no promise it cannot keep, and the element settings master lists only toggles that do something. If in-picker generation is ever built, it registers its own feature in the same change. The Airwaves tab help text in the registry still says "coming soon"; that toggle is off by default and is outside this row. The row's probe reads the three files, fails on `main` at the first arm, and fails on 10 of 10 mutations of its arms.

**Rows.** `LIVE-656`.
