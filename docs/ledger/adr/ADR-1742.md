## ADR-1742: The theme gate: check:tokens holds every literal that ignores a design

**Status:** Accepted · 2026-10-13 · owner-directed ("bullet proof for themes") · extends [ADR-781](DECISIONS.md) (the drift-guards) and [ADR-1737](DECISIONS.md) (the design switch)

**Context.** With two designs (DAWN and Frequency, ADR-1737, ADR-1740), a literal is wrong in at least one of them: `bg-white` is DAWN's paper and a hole in Frequency's night. `check:tokens` scanned `.ts`/`.tsx` for hex, `rgb()` and `text-[Npx]` only. Five other ways to write a literal went unseen: the Tailwind default palette and monochromes (counted by `check:adoption` at a floor of 0, but that gate is advisory in CI, OWN-004, so the next `bg-white` would have merged with a warning); named colours, font sizes and font families in style objects and SVG attributes; colour functions inside arbitrary classes (`_rgb(` defeats `\brgba?\(`) and every non-rgb colour function (`hsl()`, `oklch()` …); hand-written CSS, which no gate read at all; and type under Frequency's 13px floor in its hand-written sheets. The docs also still said "raw hex appears only in app/globals.css" and "DAWN tokens only", both untrue once a second design fills the same names.

**Decision.** (1) **Hard in check:tokens** (zero today, so zero forever): the palette and monochrome classes in `.ts`/`.tsx`, read from the `raw-palette` and `white-black-literals` entries of `scripts/adoption-baselines.json` (one definition, its scope and its `KEEP <utility>:` escape; the check refuses to run if either floor is not 0). (2) **A per-file ratchet in check:tokens**, `scripts/token-baselines.json`: `tsx-style-colour`, `tsx-style-font-size`, `tsx-style-font-family`, `tsx-colour-function`, `css-colour`, `css-font-family`, `css-font-size-floor`. A file may hold or lower its count; a rise, or any site in an unlisted file, fails. Per file, not a total, because ci.yml blocks only on set-shaped ratchets: a failure names the file the PR touched. `--update --reason` writes falls only; a rise needs `--allow-raise` and is recorded as raised. Generated sheets (the installer's header) are skipped; `app/globals.css` is read outside token declarations; the alias layer may carry a literal whose comment names the export value it mirrors; a mask's black is geometry, not colour; `color-mix(in oklab, …)` over tokens is not a site. (3) **One statement of the rules**, in docs/THEME.md §0 (semantic tokens, the named scale with each design's sizes, Frequency's 13px floor with the 11px label and 12px tag); THEME-PROTOCOL §3 describes the gate and links there; PRESENTATION, PAGE-FRAMEWORK, ARCHITECTURE and the plan docs that said "DAWN tokens only" now say semantic tokens.

**Rejected.** New `check:adoption` entries (advisory in CI, and its regex corpus cannot tell a CSS declaration from a selector or read a per-line comment); one total per class (a count you cannot make set-shaped should not block, per ci.yml); hard-failing the new classes now (six fix lanes were still landing).

**Consequences.** Seeded 2026-10-13 on `overhaul`: 0 palette sites; ratchet totals tsx-style-colour 0, tsx-style-font-size 21 (3 files), tsx-style-font-family 0, tsx-colour-function 3, css-colour 64 (7), css-font-family 0, css-font-size-floor 13 (6). Classes at 0 are already hard in effect. After the fix lanes merge: `node scripts/check-tokens.mjs --update --reason "<which lane retired them>"`. Proof: `scripts/check-tokens.test.ts` (positive and mutation controls per detector, and literals planted into real files).
