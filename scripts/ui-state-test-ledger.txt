# check:elements — UI-STATE-TEST LEDGER (Lift 8d of docs/UX-MATURITY-PLAN.md).
#
# Every `components/ui/*.tsx` primitive listed here ships WITHOUT a colocated state test.
# They are PRE-EXISTING DEBT, grandfathered on 2026-08-17 so the gate can start refusing NEW
# primitives without one. A primitive that is NOT on this list and has no state test FAILS.
#
# What counts as a state test (docs/INTERACTION-STATES.md §6, the machine-checkable proxy):
# a `components/ui/*.test.tsx` that IMPORTS the primitive's module and NAMES at least three of
# the nine states from §1 in its own `describe`/`it` titles. Titles only — a `.press` buried in a
# className assertion is exercising a state, not naming one, and §6 asks for the naming.
#
# RATCHET — this list may only SHRINK, and it is enforced in BOTH directions:
#   · a primitive here that GAINS a state test FAILS the gate until it is removed from this file
#     (that is the whole point: coverage bought must be banked, or the list stops meaning anything);
#   · an entry naming a file that no longer exists FAILS too (a deleted primitive is not debt).
# Both are fixed by one command, after the test lands:
#   node scripts/check-elements.mjs --update
#
# ADDING an entry is a deliberate, reviewable act and needs a reason the diff carries:
#   node scripts/check-elements.mjs --update --allow-raise --reason="why"
#
# ⚠️ WHY THE LIST IS LONG, AND WHY THAT IS NOT ALL DEBT. The gate cannot classify a primitive,
# and INTERACTION-STATES §2 assigns the required state set BY CLASS: an Action control owes six
# states, a Field four, but a Display badge owes only `rest` and a Reading only `rest` + `empty`.
# A badge can therefore never name three states honestly. So this gate OVER-REPORTS by design —
# it can only ever call a primitive undertested, never certify an untested one — and the badges,
# icons and image widgets below are on the list because of their class, not because they are
# neglected. A new one of those belongs here too, added with `--allow-raise --reason=`, which is
# a one-line reviewable claim about its class rather than a test written to satisfy a regex.
#
