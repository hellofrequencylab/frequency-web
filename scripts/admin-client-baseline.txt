# Added 2026-08-11 (ADR-986..999). Four files, each the ONLY path to a table that is
# deliberately unreachable any other way:
#   lib/events/seed/store.ts   event_intake — RLS enabled, ZERO policies, service-role only
#   lib/studio/steer-store.ts  studio_steer — same posture; holds an author private note to Vera
#   lib/ai/vera/create-entity.ts  writes the agent_actions audit trail the autonomy ladder is
#                                 earned against; a caller must not be able to edit its own audit
#   lib/loom/cover-actions.ts     files a generated cover into library_assets, re-gating
#                                 canEditProfile itself before it writes
# The session client cannot reach a zero-policy table by construction, so converging these is
# not a matter of effort: it would mean giving those tables client-readable policies.
# lib/billing/bundle-seats.ts (added 2026-08-12, ADR-370): the Stripe webhook seating branch for the
# Household / Circle bundle. There is no session to run under — the caller is Stripe, and the write is
# apply_bundle_seating_atomic, a SECURITY DEFINER function granted to service_role ONLY (migration
# 20270225000000 revokes anon + authenticated). Converging it onto the session client is not possible
# by construction. Same posture as lib/billing/bundle-checkout.ts directly above.
# lib/billing/bundle-invites.ts (added 2026-08-12, ADR-370): the post-purchase seat invites for the
# Household / Circle bundle. household_bundle_invites is RLS-on with ZERO policies (deny-all, see
# scripts/rls-deny-all.txt) and the two seat writes are SECURITY DEFINER functions granted to
# service_role ONLY (migration 20270226000100 revokes anon + authenticated on both the table and the
# functions), so the session client cannot reach any of it by construction. Every read and write here
# is bound to the caller's own profile id, re-resolved from the session by the action layer.
# studio_draft is RLS-on-no-policy (zero policies, grants revoked from anon/authenticated), so the
# session client cannot reach it at all: staged wizard answers are unfinished writing and the table
# is deliberately unreachable except through this one owner-scoped file. Every query filters on a
# session-derived profile_id, which IS the access control (ADR-1001, mirrors lib/studio/steer-store.ts).
#
# Added 2026-08-12 (ADR-1014, ADR-1016). Two files, each re-gating authorisation ITSELF
# before it acts, which is why the bypass is the safe shape rather than the lazy one:
#   app/(main)/circles/[slug]/(circle)/members/actions.ts
#       setCircleMemberRole re-resolves the caller's capabilities against the LIVE circle on
#       every request and refuses without circle.manageRoles. It must read circles.host_id to
#       enforce the last-owner guard — the row a non-member cannot see under RLS, which is
#       exactly the row the guard depends on. Fails closed on any role outside the three
#       assignable rungs, so a client asking to mint an owner is rejected before the read.
#   lib/circles/effort-board.ts
#       Reads zap_transactions for members of one circle, behind the CALLER's gate: the page
#       renders rows only for circle members. The effort index is deliberately a WHOLE-LIFE
#       denominator per member, so it cannot be scoped by the circle's own RLS without
#       changing the number the member is measured against.
#
# Added 2026-08-12 (the Circle five-tab restructure). Two files, both in the circle detail
# path that already runs on the service-role client (loadCircleShell), and both applying the
# visibility rules BY HAND because the bypass makes RLS invisible to them:
#   app/(main)/circles/[slug]/(circle)/tab-facts.ts
#       Decides which tabs exist, so it must answer "is there anything here for THIS viewer"
#       before the shell renders. Its event read carries the full predicate — status=published,
#       is_cancelled=false, removed_at is null — plus an insider-aware `visibility` list, so a
#       members-only event grows the Events tab only for someone on the roster. Getting this
#       wrong leaks by TAB COUNT rather than by row, which is why it is stated here.
#   components/admin/modules/circle-journey-run-actions.ts

#       circle.editSettings, before any journey data is read. The gate is the first thing it
#       does, not a filter on the way out.

# lib/events/guest-rsvp-email.ts (added 2026-08-13): composes the confirmation email for a
# SIGNED-OUT guest RSVP (20270303000000). The bypass is the reason the module exists: it must read
# whether the seat landed as `going` or `waitlist`, and the reader is anon — event_rsvps' SELECT
# policy grants a row to its own profile or to a host, and a guest is neither, so under RLS this
# read returns nothing. Converging it onto the session client would mean giving anon a policy that
# lets it read RSVP rows by email, which is precisely the address oracle capture_guest_rsvp was
# shaped to avoid. Quarantined here rather than left in the server action so the action itself stays
# on the session client: capture_guest_rsvp is granted to anon and reachable over PostgREST, so the
# action is not a security boundary and must hold no power the SQL is not already assuming. The
# status reaches the email body only, never the HTTP response.
