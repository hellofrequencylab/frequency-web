# Function-grant contract — one EXECUTE verdict per live `public` function (LIVE-020, ADR-959).
# Enforced by `pnpm check:function-grants` (scripts/check-function-grants.mjs).
#
#   public         a signed-out visitor must be able to call it. Reached as `anon` through
#                  lib/supabase/public.ts, or through lib/supabase/server.ts on a page a
#                  signed-out visitor can load.
#   authenticated  signed-in callers invoke it with the anon key; anon must NOT. REQUIRES an
#                  explicit `revoke ... from ... anon` in a migration -- the gate checks.
#   internal       service_role only (or a trigger function, or an RLS helper). REQUIRES the
#                  same explicit revoke.
#
# BOTH non-`public` verdicts are load-bearing here, which is where this file differs from
# scripts/table-grants.txt. On a table, RLS is the second lock and `authenticated` describes a
# policy. A SECURITY DEFINER function bypasses RLS by construction, so the grant is the ONLY
# lock and "signed-in only" is a claim about the grant and nothing else.
#
# WHY THIS FILE EXISTS. PostgREST publishes every function in `public` as an RPC. Supabase's
# `ALTER DEFAULT PRIVILEGES IN SCHEMA public` grants anon and authenticated EXECUTE on each new
# one as EXPLICIT per-role grants, and Postgres separately grants EXECUTE to the pseudo-role
# PUBLIC. `revoke ... from public` does not touch the first; `revoke ... from anon` does not
# touch the second. Either statement alone succeeds and locks nothing (ADR-959). The gate
# therefore demands a revoke that NAMES THE ROLE, and rejects a public-only revoke by name.
#
# HOW THE VERDICTS WERE SEEDED -- FROM THE LIVE CATALOG, NOT FROM THE SQL. Measured against
# production (azsqfeonabsbmemvddqd) on 2026-08-17 with has_function_privilege:
#   public         = anon holds EXECUTE today and that is accepted
#   authenticated  = anon does not, authenticated does
#   internal       = neither
# Twelve rows then differ from that measurement on purpose: they are OWN-006's decisions,
# applied by 20270304000000, where a function anon can reach today is one no browser calls.
#
# THE PARSE WAS CROSS-CHECKED AGAINST THE CATALOG BEFORE THIS FILE WAS WRITTEN, and the check
# earned its keep twice. Replaying supabase/migrations/ yields exactly the 148 non-extension
# functions production holds in `public` -- 148 <=> 148, zero drift in either direction. Getting
# there caught a parser that processed every create before every drop (nine functions lost to
# `drop ...; create ...` in one file) and a name-granular liveness model that erased
# `record_qr_scan` when one of its two overloads was dropped. A gate cannot protect an object
# its parser cannot see.
#
# `public` is a DECLARATION the gate does not verify -- it cannot read a function body and it
# cannot tell an anon-safe aggregate from an anon-reachable oracle. That is
# supabase/migrations/fail-open-guards.test.ts's job (ADR-961). Keep both. If you are unsure,
# write `internal`: it is the only verdict that fails closed.
#
# NOT LISTED, on purpose:
#   · the 18 RLS helpers moved to schema `private` by 20270101000000 -- off the REST surface
#     entirely, and declared in RETIRED_BY_DYNAMIC_SQL in the guard.
#   · `st_estimatedextent` (3 overloads) -- owned by extension `postgis` and granted by
#     `supabase_admin`, so no migration of ours can revoke them.
#
