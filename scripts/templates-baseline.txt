# check:templates baseline — every in-app page.tsx that renders JSX and composes NO kit shell,
# in the page itself or any ancestor layout (PAGE-FRAMEWORK §3). A SET, not a count: a page
# adopting a template and a new bare page arriving can no longer net to zero and stay green.
#
# RATCHET: this list may only SHRINK. Convert a page to a template, then regenerate:
#   node scripts/check-templates.mjs --update
# Adding a bare page is a deliberate, reviewable act and needs a reason the diff carries:
#   node scripts/check-templates.mjs --update --allow-raise --reason="why"
#
# ⚠️ Three entries are compliant pages the gate cannot see (ADR-986): app/(main)/classifieds/new,
# app/(main)/spaces/[slug]/settings/services/new and app/(main)/market/sell are SERVER pages that
# gate and then delegate to a client Spark which composes SparkShell. The gate matches literal tags
# in the page file by design — it over-reports rather than certifying a hand-rolled layout — so they
# are listed here. market/sell joined them on 2026-08-24 (ADR-914 / OWN-032): its FocusTemplate was
# the upgrade WALL, so opening the Market to free members removed the composition with it.
#
# ⚠️ Six entries are PRESENTATIONS of a page, not pages (ADR-1017): the app/(main)/@wizard/(.)…
# intercepting routes. Each one imports and renders the SAME page module its real route serves,
# wrapped in the Spark modal, so the kit shell is composed by the page underneath and by the
# wizard's own SparkShell. There is no second layout here to convert: giving one a template would
# put a page header inside a dialog. They are BASELINED rather than excluded from the walk on
# purpose — a future slot page that really does hand-roll a layout must still fail this gate.
#
# The two Show pages (SCAN-644) that delegate to ShowPageView left this list on 2026-10-13: it is
# now a REGISTERED COMPOSITION (COMPOSITIONS in check-templates.mjs, verified to render
# DetailTemplate on every run), as are CaptureShell, UnsubscribeFrame, OnboardingForm and
# SequenceRunner. The eight MarketHero pages left with them: the editable-index header is a shell
# (PAGE-FRAMEWORK §8.5).
#
# ⚠️ Entries that joined when the scope widened (2026-10-13, design-switch program, ADR-1737). Each
# belongs to ANOTHER design system the change-over restyles at its own source, so none can take an
# app shell without visibly changing DAWN. Listed, not skipped, so a NEW page under these trees fails:
#   · app/discover/* landings — the marketing kit (PhotoHero / marketing PageHero / Section /
#     mk-beat beats from components/marketing). An app shell would replace a full-bleed photo hero
#     with the kit's rounded band. The /discover pages that ARE indexes already compose IndexTemplate
#     or MarketHero.
#   · app/hosted/* — a Space's website on its own domain: SitePage / SiteChrome, the site theme
#     system that app/sites (skipped) also renders.
#   · app/spotlight/[handle], app/spaces/[slug]/spotlight — a member's or Space's themed Spotlight
#     mini-site (SpotlightShell / SpaceSpotlight), its own identity header and background.
#   · app/sign-in — a full-screen PhotoHero takeover (marketing kit) around the auth card.
#   · app/join/(induction)/* — the scripted, light-locked cinematic induction and its finalizer.
