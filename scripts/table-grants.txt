# Table-grant contract — one verdict per live `public` table (ADR-964).
# Enforced by `pnpm check:grants` (scripts/check-grants.mjs), wired into ci.yml.
#
#   public         a signed-out visitor must read it. A read policy admits anon with an
#                  identity-free predicate.
#   authenticated  signed-in callers query it with the anon key. Policies exist, but every
#                  read path is gated on caller identity.
#   internal       service_role only. REQUIRES an explicit
#                  `revoke ... from anon, authenticated` in a migration -- the gate checks.
#
# WHY THIS FILE EXISTS. Supabase ships `ALTER DEFAULT PRIVILEGES IN SCHEMA public`, so anon and
# authenticated hold table grants on every new table the moment it is created, and
# `REVOKE ... FROM public` does not remove them (ADR-959). Before the 2026-08-10 sweep, only
# SEVEN of 272 tables carried any explicit grant decision at all.
#
# The verdicts were SEEDED FROM THE LIVE DATABASE (RLS + policy state), not guessed:
#   internal      = RLS on, zero policies
#   public        = a SELECT policy admitting anon whose USING references no caller identity
#   authenticated = everything else with policies
#
# `public` and `authenticated` are DECLARATIONS. The gate does not verify them -- it cannot read
# a policy predicate, and it cannot see column grants (ADR-964 was exactly that: a correctly
# `public` table with an anon-readable stripe_customer_id column). `internal` is the load-bearing
# one, and it is the only verdict that fails closed. If you are unsure, write `internal`.
#
# 39 public · 155 authenticated · 78 internal · 272 total
