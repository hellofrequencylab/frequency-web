Foundations · Type

Type scale · roles not pixels

There are no arbitrary sizes. Each token names the job it does, so "make this bigger" becomes "this is a section heading, not a card title" — a content decision instead of a number.

Display · Anton

--text-display-heroclamp 3–5remThe PhotoHero H1. One per page.
--text-display-h1clamp 2.75–4.5remA page that opens on type instead of a photograph.
--text-display-h2clamp 2.25–3remSection headings. The workhorse.
--text-display-h3clamp 1.75–2.25remA beat inside a section.
--text-display-card1.5remA card title in the display voice.
--text-statclamp 3.5–4.5remThe big numeral in a proof block.

Sans · Nunito

--text-page-title1.5remThe in-app template header.
--text-lead1.25remIntro paragraph or kicker.
--text-card-title1.0625remA sans card title.
--text-body1remDefault body copy.
--text-body-sm0.875remIn-app body and descriptions.
--text-meta0.75remCounts, timestamps, labels. The content FLOOR.
--text-2xs0.6875remChrome only: a rank chip, a tab count.
--text-3xs0.625remChrome only: the smallest legal line. Exists so nobody writes 10px ad hoc.

Roles, not pixels. If no token fits, the content is probably mislabelled — not the scale short a size.

Two sub-xs steps exist so they are never invented. They are chrome, never content.

One display face per block. A heading is Anton or Nunito, not both.

clamp does the responsive work. Do not add breakpoint overrides on type.
